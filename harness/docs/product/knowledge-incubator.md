# 知识孵化工作台需求设计

> 版本：v1.1  
> 日期：2026-08-14  
> 状态：首期六段已实现并验证；已补齐固定 L12 精排、三池批量丢弃与可恢复归档
> 适用范围：知识孵化产品基线；后续实施必须拆分为短生命周期 active spec

## 1. 目标

在现有单管理员博客后台增加“知识孵化”工作台，把管理员主动提供的 Markdown、TXT 和一次性网页正文，与博客中已发布文章进行本地混合检索和第三方 LLM 审计，再经过人工裁决、孵化草稿与最终发布闸门，沉淀为可追溯、可回滚的标准知识库。

首期成功不是“AI 自动写文章”，而是建立下列受控闭环：

```text
批量摄入
  → 清洗与精确去重
  → 待处理池人工触发
  → 已发布文章混合检索
  → 单次 LLM 审计
  → 人工确认或裁决
  → 孵化草稿
  → 编辑、重生成与预览
  → 确认并发布
  → 文章版本、来源与 Token 留痕
```

## 2. 产品原则

- **只审计已发布文章**：现在和未来均不把文章草稿、项目或读书笔记纳入旧文检索语料。
- **先审计后生成**：资料未经审计确认不得生成孵化草稿。
- **人工控制付费调用**：清洗和检索不触发第三方 LLM；审计和生成只能由管理员显式发起。
- **唯一最终发布闸门**：AI 产出先进入独立孵化草稿池，只有“确认并发布”才改变公开知识库。
- **维护标准知识而非正反陈列**：冲突先阻断并等待裁决，不自动生成反方补丁或反论文章。
- **原始资料不可被清洗结果替代**：原始层与标准化层并存，可重新清洗、审计和追溯。
- **失败显式、任务幂等**：抓取、模型、LLM、索引和发布失败均有状态、错误、重试和幂等保护。
- **个人项目成本优先**：以 2 vCPU / 4 GB 单机为首期部署基线，接受后台任务分钟级延迟。
- **高危基础设施默认禁止**：Redis、Celery 和独立消息队列不在首期实现。嵌入式 Zvec 只作为 E5 向量的派生存储，不取代 SQLite 事实库，也不改变 FTS5／RRF／Cross-Encoder 策略。

## 3. 首期范围

### 3.1 摄入入口

支持一次批量提交下列资料：

- `.md`、`.markdown` 文件；
- `.txt` 文件；
- 一个或多个公网 `http/https` 网页链接。

一个文件或 URL 对应一条独立资料。批量只是录入效率能力，不会把多份资料合并为一个知识对象。

### 3.2 批次与资源限制

- 单批文件与 URL 合计最多 50 项。
- 单文件最多 2 MiB。
- 单批上传文件合计最多 10 MiB。
- 单个网页响应最多读取 5 MiB。
- 提取后的单篇正文最多 2 MiB。
- 批次采用部分成功：每项独立成功、失败与重试，不因单项失败回滚整个批次。

### 3.3 文件编码

- 优先使用 UTF-8 或 UTF-8 BOM。
- 失败后尝试 GB18030。
- 两者都不能解码时明确失败，不继续不确定的编码猜测。
- 标准化正文统一保存为 UTF-8，并记录检测到的原始编码。

### 3.4 URL 边界

URL 是一次性正文输入，不是订阅源：

- 仅在提交时抓取一次；抓取后不监控、不定时刷新、不维护远端更新状态。
- 原始 URL 只作为来源证明保留。
- 后续再次提交同一 URL 视为新的摄入事件，再由正文指纹判断是否重复。
- 不执行 JavaScript，不携带浏览器登录态或管理员 Cookie。
- 不绕过登录、付费墙、反爬限制或访问控制。
- 只允许公网 `http/https`；阻止 localhost、环回、私网、链路本地地址及重定向到这些地址。
- 每次重定向都必须重新执行地址与 DNS 安全校验，防止 SSRF 和 DNS rebinding。
- 依赖 JavaScript 才能得到正文的页面明确失败，管理员可改用文件摄入。

### 3.5 标题生成

标准化标题按以下顺序生成，并允许在审计前修改：

- Markdown：Frontmatter `title` → 第一个 H1 → 文件名；
- TXT：第一行短标题 → 文件名；
- URL：Open Graph／`<title>` → 第一个 H1 → 域名与路径。

系统保留原始标题和标准化标题；修改标准化标题不改写原始层。

### 3.6 Frontmatter

Markdown 只解析有限来源字段：

- `title`
- `author`
- `source_url`
- `published_at`
- `tags`（只作审计与分类建议参考）

未知字段保留在原始文件，但不进入业务逻辑；标准化正文移除 Frontmatter。解析必须使用安全 YAML，禁止对象构造、anchor/alias 和复杂嵌套。来源标签不能自动创建或写入博客栏目与标签。

### 3.7 原始层与标准层

每条资料保留：

- 原始字节、文件名或 URL、MIME、编码、抓取时间、校验值；
- URL 抓取到的原始 HTML；
- 清洗后的标准化 Markdown、标题和来源元数据；
- 清洗器版本、资料修订号和修改历史。

原始字节和 HTML 使用压缩 BLOB 保存在 SQLite；标准化 Markdown 使用文本字段保存。原始 HTML 只能按纯文本或经过严格净化的方式展示，绝不直接注入管理页面。

### 3.8 清洗与确定性校验

自动执行：正文提取、HTML 清除、广告与导航噪声过滤、Markdown 规范化、换行和空白归一化、有限 Frontmatter 处理、编码检查、空正文和明显乱码检查。

被动摄入不引入内容质量评分模型。是否值得审计由管理员在待处理池决定。

### 3.9 精确去重

- 对标准化正文计算稳定内容指纹。
- 同一文件重复上传、同一 URL 重复提交、不同 URL 但正文完全相同，均识别为精确重复。
- 重复资料不再创建第二条可审计项，不重复消耗 Token。
- 本次摄入事件、来源和时间仍留痕，并关联首次资料。
- 内容指纹继续覆盖已丢弃资料，防止相同内容反复进入系统。
- 首期不实现语义去重。

### 3.10 审计前人工修正

- 待处理池提供原始内容与标准化 Markdown 对照预览。
- 管理员可修改标准化标题和正文；每次修改保存新修订，不覆盖原始层。
- 修改后重新计算指纹、Token 估算和检索输入。
- 审计开始时冻结本次资料修订。
- 审计完成后再修改资料，会使旧报告失效，资料退回待处理状态。

## 4. 三个汇聚池与状态机

### 4.1 信息架构

管理导航新增“知识孵化”：

- `/admin/incubator`：概览、摄入入口、池数量、任务与模型健康度；
- `/admin/incubator/inbox`：待处理池；
- `/admin/incubator/audits`：审计报告池；
- `/admin/incubator/drafts`：孵化草稿池；
- `/admin/incubator/tasks`：任务中心。

三个池共享来源、类型、状态、时间、关键词筛选和当前页批量选择。详情必须可通过稳定 URL 定位，支持浏览器前进、后退和复制链接。

### 4.2 核心状态

```text
资料
排队中 → 摄入处理中 → 待处理 → 审计中 → 已审计
                    ├→ 重复
                    ├→ 失败
                    └→ 已丢弃

审计报告
排队中 → 判定中 → 待审阅
                  ├→ 冲突待裁决
                  ├→ 已确认
                  ├→ 已丢弃
                  ├→ 已失效
                  └→ 失败

孵化草稿
排队中 → 生成中 → 待确认
                  ├→ 重生成中 → 待确认
                  ├→ 发布中 → 已发布
                  ├→ 已失效
                  ├→ 已丢弃
                  └→ 失败
```

取消、失败和重试不得跳过前置状态。资料修订、目标文章版本变化、分类冲突或发布前复检失败都必须通过显式状态呈现，不能静默复用旧结果。

### 4.3 丢弃与永久删除

- 普通“丢弃”是逻辑归档，记录原因、操作者和时间，可筛选、查看和恢复。
- 已丢弃记录不出现在默认工作列表，也不能继续流转。
- 待处理、审计报告和孵化草稿支持当前页批量丢弃：只操作明确勾选项，查询、换页或刷新会收敛选择；运行中的审计、生成或发布项不可勾选。
- 批量丢弃二次确认，保存默认原因与可选说明，允许部分成功并返回逐项失败原因。
- 已丢弃来源、审计和草稿可逐条恢复；审计和草稿恢复前校验依赖，依赖失效时保持不可继续流转的 stale 状态。
- 永久删除只能逐条执行并二次确认。
- 已进入文章版本来源链的资料不能永久删除，只能隐藏或脱敏。

## 5. 异步任务

### 5.1 架构

首期使用 SQLite `jobs` 表与单独 Python Worker：

- API 只创建任务、取消排队任务并查询状态；
- Worker 串行领取任务，模型任务并发固定为 1；
- 任务保存类型、状态、进度、尝试次数、租约、错误和幂等键；
- Worker 崩溃或服务器重启后，过期租约任务可安全重新领取；
- 抓取、清洗、索引、本地推理、LLM 审计和生成均不得阻塞浏览器请求。

### 5.2 重试

- 本地确定性步骤按幂等键安全重试，不产生重复资料、报告、草稿或文章版本。
- 第三方 LLM 的超时、限流和 `5xx` 最多自动重试 2 次，并采用退避等待。
- 鉴权失败、模型不存在、请求格式错误不自动重试。
- 自动重试耗尽后进入失败状态，管理员可人工重试。

### 5.3 取消

- 排队任务可以立即取消。
- 抓取、清洗、索引和本地模型任务在安全点取消，并保留已完成步骤。
- 第三方 LLM 请求发出后不保证停止计费；取消只阻止后续业务步骤，调用和 Token 仍留痕。
- 最终发布事务开始后不可中途取消，只能完成或失败。

## 6. 已发布文章索引

### 6.1 唯一语料边界

混合检索始终只覆盖当前已发布且未删除的文章：

- 不含文章草稿；
- 不含项目；
- 不含读书笔记；
- 不含已删除文章；
- 不因未来功能扩展而默认扩大语料范围。

任何扩大语料类型的改变都必须单独确认。

### 6.2 切片

- 优先按 Markdown 二级、三级标题切片。
- 每片目标 320–400 Token，相邻片段重叠约 50 Token。
- 每片附带文章标题和完整标题层级路径。
- 代码块尽量保持完整；超长代码块再按行安全拆分。
- 列表、表格和引用块尽量不从中间截断。
- 片段保存文章 ID、发布修订号、片段序号、正文快照和模型版本。

### 6.3 混合检索链路

```text
FTS5 关键词召回 Top 20
        +
multilingual-e5-small 语义召回 Top 20
        ↓
合并去重与轻量排名融合
        ↓
mmarco-mMiniLMv2-L12-H384-v1 对 Top 15–20 精排
        ↓
按门槛动态输出最多 Top 8
        ↓
一次 LLM 审计
```

- 不为了满足数量而填入低相关旧文。
- 候选不足时允许传入少于 5 篇，甚至 0 篇。
- 每篇只向 LLM 提供文章摘要和最相关的 1–3 个片段，不提供旧文全文。
- LLM 在同一次审计中忽略残余不相关候选，不增加独立的 LLM 精筛调用。

### 6.4 本地模型

首期 compact 组合：

- 嵌入：`intfloat/multilingual-e5-small`，一个模型同时处理中文和英文，输出 384 维向量；
- 重排序：`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`，固定 revision 的中英双语 L12 Cross-Encoder；
- 两者均使用固定 revision、文件校验值和 ONNX INT8；
- 由单一 Retrieval Service 持有实例；是否常驻由 2 vCPU／4 GB 资源门槛决定，未达标时按需顺序加载并释放；
- 运行时不自动联网下载或跟随模型仓库 `main`；
- 模型二进制不提交 Git。

L6 候选因许可证、模型卡或中文覆盖核验未通过，已回退到该文档完整、许可证明确的 L12 模型。更换精排模型必须重新执行检索质量验证，但不重建向量。

### 6.5 模型准备与更新

- 提供独立模型准备命令，在部署阶段下载并校验必要文件。
- 模型未配置、文件缺失或校验失败时，工作台显示“本地检索模型未就绪”，不允许正常审计。
- 更换嵌入模型必须重建全部向量索引。
- 更换重排序模型无需重建向量，但必须重新执行检索质量验证。

### 6.6 向量存储

- SQLite 仍是文章、发布修订、片段和活动状态的唯一事实库；`article_embeddings.vector` 继续保存紧凑二进制向量，供 NumPy 回退与全量重建。
- 在线语义召回可以使用嵌入式 Zvec Flat（384 维 L2 归一化 FP32、内积与 NumPy 等价）；Zvec 只保存活动或待切换 generation，不保存草稿或非当前发布修订。
- 默认查询后端是 `numpy`；切换到 `zvec` 必须通过固定查询集等价性门槛，并在目标 2 vCPU／4 GB 实例上满足资源门禁。
- 当有效片段超过 50,000 或实测延迟不达标时，只触发重新评估，不自动改用近似索引或更换模型。

### 6.7 索引一致性

- 文章发布事务创建文章版本并登记待索引任务，但不在事务内加载模型。
- 文章发布不因索引任务失败而回滚。
- 新索引完成后原子切换到新发布修订，再清理旧索引。
- 只要存在未完成索引的已发布文章，新审计默认暂停并显示进度。
- 管理员可以显式执行一次“仅 FTS5”应急审计；报告必须标注降级，且不能获得批量确认资格。

## 7. LLM 配置与调用

### 7.1 第三方 API

审计与生成使用 OpenAI 兼容的第三方 API：

- 环境变量配置 `base_url`、API Key、审计模型、生成模型、上下文窗口、最大输出 Token 和超时；
- API Key 不进入数据库、不返回前端、不写日志；
- 工作台只显示已配置／未配置、服务地址标识和模型名称；
- 提供最小连接测试，并区分未配置、鉴权失败、模型不存在和服务不可达；
- 配置缺失时，审计或生成前预检失败，不创建任务、不产生费用，并返回稳定错误码 `LLM_NOT_CONFIGURED`。

### 7.2 隐私与外发

- 上传、清洗、本地检索阶段不向第三方发送内容。
- 发起审计时明确提示：新资料全文和相关旧文摘要／片段将外发。
- 批量审计显示外发资料数量，管理员确认后才创建任务。
- 重生成同样属于外发；同一工作会话已确认后可不重复弹窗。
- 不实现不可靠的敏感信息自动判定。
- 日志只记录调用元数据，不记录完整提示词正文。

### 7.3 结构化输出与提示注入防护

- 来源正文和旧文片段始终被视为不可信数据，不能作为系统指令执行。
- 审计与生成使用版本化系统提示词和严格结构化响应模型。
- 供应商支持原生结构化输出时优先使用；否则解析 JSON 后执行同等严格校验。
- 文章 ID、片段 ID、角色、目标文章、证据和字段长度全部由后端验证。
- 引用不存在的 ID 或越权目标时，结构化结果失败并按 LLM 重试规则处理。

### 7.4 Token 记录

- 不设置日、周或金额配额，不因 Token 消耗阻止任务。
- 发起前展示预计 Token。
- 每次调用记录输入、输出、总 Token、模型、任务类型、时间、尝试号和重试关系。
- 供应商返回 `usage` 时标记为实际值。
- 未返回时使用对应 tokenizer 估算；无法识别 tokenizer 时使用通用近似并标记低精度估算。
- 工作台按日、周和任务类型汇总，只用于观察。

### 7.5 超长资料

超长资料是受控异常路径：

- 审计前按配置模型精确估算上下文占用；
- 需要为提示词、最多 8 篇旧文片段和输出保留空间；
- 超过单次上下文时不截断、不调用 LLM，并提示管理员拆分或精简；
- 首期不实现自动分段审计和多轮汇总；
- 记录发生次数，只有真实使用证明频繁出现时才重新评估。

每次“重新审计”都是独立、无状态的新调用，不继承上一轮上下文。

## 8. LLM 审计

### 8.1 触发

- 清洗完成只进入待处理池，不自动调用 LLM。
- 管理员可勾选多条并统一发起，但每条资料独立检索、独立 LLM 调用、独立报告和独立失败。
- 首期不把多条新资料合并进一次调用。

### 8.2 角色

一份资料只能产生一个主角色：

| 角色 | 目标文章 | 含义 |
| --- | --- | --- |
| 增补 | 必须且仅一篇 | 旧知识成立，需要补充边界、证据或新内容 |
| 重构 | 必须且仅一篇 | 旧文需要显著修正或整篇重写 |
| 冲突待裁决 | 必须且仅一篇 | 新旧结论冲突，必须人工裁决后才能继续 |
| 新分支 | 无 | 新资料形成独立知识主题 |

其他相关旧文只作参考关联。资料包含多个可独立落地知识点时，报告提示管理员拆分资料后重新审计。

### 8.3 报告字段

报告至少包含：

- 主角色、置信分数和等级；
- 判定理由；
- 主目标文章及绑定发布修订号；
- 其他相关旧文；
- 预计产出类型和范围；
- 新资料证据；
- 旧文章证据；
- 风险与不确定性；
- 检索模型、模型版本、候选数量、提示词版本和第三方模型；
- Token 使用和调用尝试记录。

### 8.4 证据硬门槛

- 每个关键判断至少引用一处新资料片段。
- 增补、重构和冲突还必须引用旧文章标题、版本和章节片段。
- 引用保存稳定片段 ID 与文本快照，旧文章以后变化仍能回看当时证据。
- 无效引用使整份结构化报告失败，不能进入人工确认。

### 8.5 人工改判

- 管理员可以直接修改角色和主要目标文章。
- 改为新分支时清空目标文章；改为其他角色时必须选择一篇目标文章。
- 系统保存 AI 原判、人工改判、操作者、时间和可选备注。
- 人工改判与“重新判定”是不同操作。

### 8.6 冲突裁决

冲突待裁决是阻断状态，不能直接生成草稿。管理员必须选择：

- 转为增补；
- 转为重构；
- 转为新分支；
- 丢弃资料；
- 暂缓裁决，继续留在报告池。

系统保留 AI 原始冲突判断、冲突证据和最终人工裁决。由冲突改判产生的草稿始终逐条发布。

### 8.7 置信与批量确认

- 高置信门槛为 `≥ 0.95`，阈值由后端配置并在前端显示。
- 重构和冲突始终高风险，只能逐条审阅。
- 高置信且无结构风险的增补可批量确认。
- 高置信新分支可批量确认。
- 低于 0.95 的任何报告不得批量确认。
- 丢弃可批量执行；重新判定始终逐条执行。

### 8.8 重新判定

- 必须填写反馈，避免无反馈重复消费 Token。
- 新审计保存为独立版本，不覆盖旧报告。
- 新调用包含当前资料修订、最新检索结果、旧报告和反馈。
- 资料或索引变化时必须重新检索，不能复用旧候选。

### 8.9 报告失效

- 增补、重构和冲突报告绑定主要目标文章的发布修订号。
- 目标文章产生新版本后，报告立即失效，必须重新审计。
- 其他参考文章变化只显示警告。
- 新分支在最终发布前执行免费本地相似性复检；出现高度相似的新文章时阻止发布并要求重新审计。

## 9. 孵化草稿

### 9.1 独立暂存

- 所有 AI 产出先保存到独立孵化草稿池。
- 生成过程不修改现有文章，也不创建普通文章草稿。
- 草稿关联来源资料修订、审计报告版本、角色、目标文章版本和生成尝试。

### 9.2 增补

生成结构化补丁：

- 目标二级或三级标题；
- 插入位置；
- Markdown 内容；
- 引用与来源；
- 合并前后差异预览。

发布前重新校验目标文章版本和标题锚点。文章变化、锚点消失或结构冲突时阻止自动合并，要求重新选择位置或重新生成。禁止无条件追加到正文末尾。

### 9.3 重构

- 生成完整新正文，并可建议新标题和摘要。
- `slug`、首次发布时间、栏目和标签默认不变。
- 管理员决定是否采用建议标题和摘要。
- 最终发布创建新文章版本，旧版本可查看和回滚。
- 目标文章在生成后变化时阻止覆盖并要求重新审计。

### 9.4 新分支

发布前必须确认：

- 标题；
- 唯一 slug；
- 摘要；
- 一个栏目；
- 至少一个标签。

AI 只能从现有栏目和标签中推荐，不能擅自创建分类。slug 冲突时阻止发布，不自动添加后缀；同时展示冲突文章，提示重新判断是否应改为增补或重构。

### 9.5 编辑与自动保存

- 复用现有 Markdown 编辑器、自动保存和版本号乐观锁。
- 保存冲突返回 `409`。
- 保存失败时禁止“确认并发布”。
- 后台任务不得静默覆盖人工编辑。
- 发布前等待当前及最新排队保存完成，再执行目标文章与结构校验。

### 9.6 重生成

- 重生成必须填写反馈。
- 不覆盖旧草稿，创建新生成版本。
- 新提示包含原审计结论、上一版草稿和反馈。
- 默认展示最新版，但可查看版本差异并选择历史版本继续编辑或发布。
- 每次生成记录模型、提示词版本和 Token。

## 10. 发布、溯源与版本

### 10.1 最终动作

“最终确认”明确命名为“确认并发布”：

- 增补：结构校验后合并补丁并发布目标文章新版本；
- 重构：替换正文并发布目标文章新版本；
- 新分支：创建并发布新文章；
- 冲突待裁决：无发布资格。

### 10.2 有限批量发布

- 高置信新分支在分类完整、复检通过时可批量发布。
- 高置信增补在目标版本和章节锚点校验通过时可批量发布。
- 重构始终逐条发布。
- 冲突改判而来的草稿始终逐条发布。
- 批量发布使用部分成功；失败项留在草稿池并显示原因。
- 最终弹窗列出将公开变更的文章，必须人工确认。

### 10.3 全局文章发布版本

文章版本历史覆盖所有正式发布，不只覆盖孵化系统：

- 每次普通编辑器发布、孵化发布和回滚都创建不可变版本。
- 自动保存不创建正式发布版本。
- 版本保存标题、摘要、正文、栏目、标签、发布时间、变更来源和校验值。
- 孵化版本额外关联资料、审计报告和草稿。
- 回滚通过创建一个内容等同历史快照的新版本完成，不删除历史。

现有 `version` 继续承担编辑乐观锁；新增独立发布修订号。

### 10.4 存量迁移

- 现有已发布文章当前内容迁移为基线发布版本 1。
- 不伪造升级前不存在的历史。
- 草稿文章不创建发布版本，首次发布时创建版本 1。
- Alembic 只创建基线与待索引状态，不在迁移中加载模型。
- 迁移后 Worker 异步建立全部已发布文章索引；完成前审计不可用并显示进度。

### 10.5 来源溯源与公开引用

- 后台永久关联资料、审计报告、孵化草稿和文章版本。
- URL 来源可在公开文章末尾形成“参考资料”，展示页面标题和原始链接。
- 上传文件默认只作后台溯源，不公开文件名或原始文件。
- 管理员可编辑或关闭公开引用，但内部来源链不可抹除。

## 11. 数据概念模型

实施规格可调整表名，但不得改变实体职责：

| 实体 | 职责 |
| --- | --- |
| 摄入批次 | 一次批量提交及汇总结果 |
| 资料 | 独立文件或 URL 的生命周期、来源与当前修订 |
| 资料修订 | 标准化标题／正文的不可变历史 |
| 原始载荷 | 压缩原始字节或 HTML、MIME、编码和校验值 |
| 摄入事件 | 重复提交的来源、时间和关联首条资料 |
| 任务 | 持久化异步执行、租约、进度、错误和幂等键 |
| 文章发布版本 | 全局不可变发布快照与来源 |
| 文章片段 | 结构化切片、正文快照和标题路径 |
| 文章嵌入 | 384 维向量、模型 revision 和片段关联 |
| 审计报告／尝试 | 角色、目标、证据、置信、人工改判与模型信息 |
| 孵化草稿／版本 | 生成结果、人工编辑、反馈、差异与发布状态 |
| 来源关联 | 资料／报告／草稿到文章版本的溯源链 |
| Token 账本 | 实际或估算的输入、输出和总 Token |

所有瞬时时间继续遵守项目 UTC-aware 边界；所有迁移只能通过 Alembic。

## 12. API 与权限边界

### 12.1 权限

- 全部知识孵化 API 位于 `/api/v1/admin/incubator` 下。
- 所有读写均要求现有管理员 Session；所有写操作要求 CSRF。
- 不新增公开摄入、审计或草稿 API。
- 公开 API 的唯一变化是文章发布版本应用后正常读取最新已发布内容和可选参考资料。

### 12.2 契约能力

具体路由在纵向实施规格中冻结，但总契约必须覆盖：

- 创建和查询摄入批次；
- 上传文件与提交 URL；
- 查询、编辑、丢弃、恢复和重试资料；
- 批量发起独立审计；
- 查询报告、人工改判、冲突裁决、重新判定和丢弃；
- 查询、编辑、重生成、丢弃和发布孵化草稿；
- 有限批量发布；
- 查询和取消任务；
- 查询本地模型、索引与第三方 LLM 健康状态；
- 查询 Token 明细与汇总；
- 查询文章版本、差异与回滚。

高增长列表继续遵守现有 `limit`／`offset` 边界、稳定排序和完整消费者分批读取规则。OpenAPI 仍是跨端契约来源，生成快照保存于 `packages/contracts/openapi.json`。

## 14. 质量与验收

### 14.1 检索基准

上线前使用真实已发布文章制作至少 30 个标注案例，覆盖中文、中文夹英文术语、英文错误信息和同义改写：

- 混合召回 `Recall@20 ≥ 95%`；
- 最小重排序后 `Recall@8 ≥ 90%`；
- 中英混合子集不得比整体低超过 5 个百分点；
- 2 vCPU / 4 GB 环境无 OOM；
- 单条本地召回与重排序在 60 秒内完成。

任一门槛失败时不能宣称模型就绪；先调整切片、融合权重或回退模型。

### 14.2 功能验收

- 混合批次部分成功且失败项可独立重试。
- 重复资料不产生第二条审计和 Token 消耗。
- 页面关闭或服务重启后任务可恢复。
- 未配置模型时明确提示且不创建付费任务。
- 资料或目标文章变化会使旧报告／草稿失效。
- 无效 LLM 引用不能进入人工确认。
- 冲突未经裁决不能生成草稿。
- 发布前保存、版本和结构校验任一失败均不能公开旧内容。
- 批量发布部分失败时成功项只发布一次，失败项保留可修复。
- 文章版本可查看差异并通过新版本回滚。
- 原始资料、审计、草稿和最终文章版本可完整追溯。

### 14.3 安全验收

- URL 抓取覆盖 SSRF、重定向、DNS 变化、超时和响应体限制测试。
- YAML 和 HTML 处理覆盖恶意结构、脚本和超限输入。
- 外部正文中的提示注入不能改变系统指令或引用越权 ID。
- API Key 不出现在响应、数据库、日志和测试快照。
- 管理写操作保持 Session、CSRF 和登录限流边界。

### 14.4 工程验收

- Alembic 迁移可从当前数据库升级，并为已发布文章创建唯一基线版本。
- Pytest 覆盖业务规则、幂等、失败恢复和契约。
- Vitest 覆盖三池状态、批量资格、Token 展示和错误映射。
- Playwright 覆盖摄入 → 审计 → 草稿 → 发布的代表性闭环，第三方和本地模型使用确定性测试替身。
- OpenAPI 快照、类型检查、生产构建、WCAG 与现有质量门禁继续通过。
- 不把模型二进制、原始资料、重日志或测试截图提交 Git。

## 15. 明确非目标

首期不实现：

- GitHub 摄入；
- Obsidian 摄入；
- 手动粘贴正文；
- 主动发现、定向爬取和兴趣画像；
- 定时 URL 抓取或网页更新监控；
- PDF、Word、HTML 文件和图片 OCR；
- 登录网页、付费墙或 JavaScript 浏览器抓取；
- 语义去重；
- 来源质量评分模型；
- 超长资料自动分段审计；
- 多份新资料合并成一次 LLM 调用；
- 跳过人工闸门或自动发布；
- 远程或跨主机向量服务、Zvec 原生 FTS／近似索引，或删除 NumPy 回退；
- Redis、Celery 或独立消息队列；
- 多用户、审批流和角色权限；
- 存量文章定时体检；
- Token 配额、金额预算或消费阻断。

任何非目标不能在实施中“顺手加入”。远程向量服务、消息基础设施、存储迁移和部署拓扑扩张属于高危变化，必须另建规格并人工确认。

## 16. 纵向交付顺序

总设计不作为一次性大改实施。首期六段已按依赖交付并关闭：

1. **摄入与清洗**：文件／URL、批次、原始层、标准层、精确去重、待处理池。
2. **检索与索引**：文章发布版本、切片、FTS5、嵌入、L12 重排序、索引状态。
3. **LLM 审计**：第三方配置、角色、证据、人工改判、重审和 Token 账本。
4. **孵化草稿**：生成版本、自动保存、人工编辑、反馈重生成和结构化补丁。
5. **发布闭环**：合并校验、来源、全局文章版本、回滚和有限批量发布。
6. **工作台整合**：统一导航、筛选、任务进度、健康状态和端到端质量门禁。

工作台整合之后已补齐三池批量丢弃与可恢复归档。新的行为、存储或模型变化仍须创建独立 active spec，并满足当前 SDD、VDD 与 Harness 关闭流程。

## 17. 未来重新评估触发器

以下事实只触发评估，不自动授权变化：

- 有效文章片段超过 50,000；
- 2 vCPU / 4 GB 上本地检索持续不能达到 60 秒门槛；
- `Recall@8` 持续低于 90%；
- 超长资料拒绝频繁影响真实工作；
- 单 Worker 队列出现不可接受积压；
- 原始资料 BLOB 明显影响备份与恢复；
- 出现多人或高并发使用需求。

评估可能涉及更大模型、独立 Worker、向量扩展、对象存储或消息基础设施，但均需新的风险评估、规格和人工批准。
