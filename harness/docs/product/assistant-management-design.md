# 问答助手管理：产品与交互设计

日期：2026-09-10。状态：第二版已落实到真实写作台，接口与存储契约见下方实施记录。原始设计讨论保留于本文后续章节；生产服务启用与新增供应商费用授权不属于本次改造。

## 1. 设计目标与依据

使用者是博客管理员。日常打开页面后，应能判断：是否向访客开放、是否需要处理问题、今天用了多少预算、公开内容是否已同步。验证回答通过后台试问完成。

已确认：统一对外启停；关闭公开问答时仍可后台试问；回答依据默认折叠；按异常给出具体处理操作；可编辑每日总预算；优先保障问答；公开内容自动同步；低频技术维护退到次级入口。本次不加入模型、提示词、价格或密钥编辑，不加入聊天记录运营分析、答案评分系统和草稿检索。

设计前快照（下列链接指向当前代码，“没有试问／预算编辑”等描述仅记录改造前状态）。当前执行、预算和公开可用性以 [已实施决策](../decisions/20260910-assistant-management.md) 及文末第二版实施记录为准：

- [当前管理页](../../../apps/web/pages/admin/assistant.vue)：四轨准入、运行事实、索引操作及三账本同屏展示；大量内部术语；没有试问和预算编辑。
- [管理接口](../../../apps/api/app/routes/admin_assistant.py)、[响应结构](../../../apps/api/app/assistant/admin_schemas.py)：已有概览、启停、索引任务重试、重建及切换接口；没有管理员试问与预算修改接口。
- [Web 边界](../../../apps/web/README.md)：访客入口由 Web 配置控制，管理页刷新为被动读；失败保留最后快照。
- [API 边界](../../../apps/api/README.md)、[运营决策](../decisions/20260829-public-qa-admin-operations.md)：聊天／查询费用在 runtime 库，索引费用在 content 库；Worker 不打开 runtime 库；切换后保持关闭；生产资格与开关相互独立。
- [索引计费](../../../apps/api/app/assistant_index/index_ledger.py)：按索引独立上限预留，sending／unknown 不安全重发。
- [导航](../../../apps/web/utils/admin.ts)、[主题](../../../apps/web/assets/css/main.css)：沿用 Gavin Studio 写作台和 Electric Editorial 双主题。

设计判断：问题主要是操作结果与处理路径不明确，而不只是信息数量。把字段折叠但仍要求管理员手动推断下一步，不能达到目标。本文未完成用户可用性测量，也没有将代码检查冒充截图审计。

## 2. 信息架构

保持侧栏原来的“问答助手”入口，页面标题为“问答助手管理”。管理工作始终位于 `/admin/assistant`，通过 `view=overview|test|maintenance` 表示可分享、可返回的页内视图；缺失或无效值回到概览。切换视图不把问题或回答写进 URL。

| 层级 | 内容 | 呈现方式 |
| --- | --- | --- |
| 概览（默认） | 开放状态、需要处理、今日费用、知识同步 | 首页主要内容 |
| 试问 | 输入、回答、回答依据、本次费用 | 与概览并列的轻量页签 |
| 高级维护 | 技术诊断、索引重建、切换、紧急停止全部问答 | 标题区低强调文字入口，不与日常操作并排竞争 |
| 局部详情 | 预算编辑、费用明细、待同步内容 | 在所属区域展开；预算编辑使用一个可访问对话框 |

不增加顶层设置中心或多层嵌套导航。诊断页始终有“返回概览”。

## 3. 概览的阅读顺序

### 标题与状态

标题下用一行解释：“管理对外开放，检查回答与内容同步。”标题区保留低强调的“刷新状态”“高级维护”。刷新只读已有事实，旁边显示“更新于 HH:mm”；不触发付费探测。

第一块使用较大状态文字，例如“已向访客开放”或“已关闭对外问答”，紧接一句访客影响。右侧仅放当前有意义的启停动作。已开放时主色按钮留给“试问助手”，关闭操作使用清晰的次级按钮；未开放且条件满足时“向访客开放”是主操作，试问为次级入口。

### 需要处理

仅有异常、等待或不确定状态时出现，位于状态下方。每项严格回答三件事：发生了什么、影响什么、如何处理。默认展示最紧迫事项，其余按严重程度列为紧凑行，不用每项一张卡。

没有问题时只显示“暂无待处理事项”，不列一排绿色服务健康徽章。该文案表示没有已知待办，不保证模型此刻可用。

### 今日费用与知识同步

桌面为并列的两个简洁区域，手机为上下排列；使用留白与一条分隔线，不做多层卡片。

- 费用：`今日已用 ¥… / 每日预算 ¥…`，一条进度条；有预留时补充“进行中预留 ¥…”；提供“修改预算”“费用明细”。未知金额显示“暂不可确认”，不补零。预算占用按已结算加预留计算。
- 同步：`公开内容已同步`／`N 项待同步`／`N 项同步失败`，标明最近成功时间，提供“查看内容”。只有确认当前公开修订与有效索引一致才可显示“已同步”；历史成功任务数量不能冒充已收录篇数。
- 示例金额、篇数和时间在视觉稿上统一标注“演示数据”，不得进入真实页面。

## 4. 状态与对外启停

“是否想开放”“实际能否接受问答”“观察是否新鲜”继续是独立后端事实，前端将其翻译成一个主结论和必要解释，不删除这些约束。

| 情况 | 首屏文案 | 操作与行为 |
| --- | --- | --- |
| 主动关闭，试问条件有效 | 已关闭对外问答；访客入口已隐藏，你仍可在后台试问 | 向访客开放；试问助手 |
| 请求开放且全部准入有效 | 已向访客开放；访客可从站点入口提问 | 试问助手；关闭对外问答 |
| 缺少部署能力或资格 | 暂时无法开放；下方给出已知具体原因 | 查看处理说明；试问按自身条件判定，不能保证可用 |
| 请求开放但额度不足 | 今日预算不足，问答已暂停；展示北京时间恢复条件 | 修改预算；关闭对外问答 |
| 服务故障或维护锁 | 问答暂不可用；显示影响和可执行处理 | 对应恢复操作；关闭对外问答仍可用 |
| 读取失败或事实过期 | 当前状态待确认；最后成功读取于… | 重试读取；可达时仍允许安全关闭，不以旧绿色状态宣称正常 |
| 提交启停中 | 正在开放／正在关闭 | 防重复提交，等待服务端确定结果；不先显示成功 |

启用：点击“向访客开放”后确认访客影响，提交一次版本化操作；阻塞时原地展示原因与处理入口，避免“成功 toast + 实际不可用”。关闭：一次有明确文案的确认，服务端安全优先；已发送的模型调用可能继续计费，但不发布被撤销范围内的正文。

统一控制需要增加服务端公开可用性投影，前端入口消费实际状态。部署环境开关仍是硬上限，管理页不修改环境变量，也不能取得生产资格。生产首次开放的原有资格流程继续适用。

访客新页面及客户端导航读取最新公开状态；已打开的页面需设计轻量失效通知或有界可用性刷新。在实现验收中固定刷新时限，不能承诺所有闲置标签页瞬间隐藏入口。即便入口短暂滞后，API 也必须立即拒绝新问题。可用性读取不创建会话、不调用模型、不返回内部诊断。

## 5. 后台试问

试问视图突出一个输入区和回答区，顶部固定提示：“仅管理员可见 · 使用当前公开知识 · 计入今日预算”。公开关闭时补充“试问不会向访客开放助手”。

初始为空，不自动填入或发送问题；示例问题点击后只填入输入框。输入支持多行、明确的发送按钮和键盘提交提示。发送中显示进度、停止按钮并锁定重复发送；不能为了动效伪造检索阶段。

回答下方是“查看回答依据（N 处）”，展开后按引用编号展示来源标题、对应证据片段、原文链接。多个引用可指向同一来源；只展示已经验证且当前允许公开的片段。无依据时明确“未找到足够依据”，不编造置信度。错误诊断以实际可观测阶段为准，不能仅凭一次未命中就断言内容未收录。

试问必须复用真实检索、模型、引用验证与费用规则；独立管理员权限和会话命名空间使其不依赖公开开放开关。它仍受到部署能力、有效配置／索引、公共资源保护、预算与维护锁限制；全局停机或数据恢复期间不可试问。匿名访客不能调用这个通道。

区分两个操作：普通“关闭对外问答”只关闭访客范围；高级维护“紧急停止全部问答”同时撤销访客和管理员执行。共享故障 fence 继续作用于两者，不能为了试问拆掉现有安全边界。

本次费用显示实际结算或“待结算”，不能以估算冒充账单。试问保留原有短会话保留与清除原则，不增加永久问答日志；提供“清空试问”。切换页签保留当前内存会话，刷新依服务端短会话恢复合同；不把正文写入浏览器持久存储。停止或离开界面不承诺供应商费用撤销。

## 6. 每日总预算

对用户只有一个人民币每日上限，按北京时间 00:00 换日。三类费用继续可展开查看，聊天与问题检索明细可区分访客／后台试问。总预算是应用按配置价格执行的费用控制，不保证供应商账单或计算机器成本。

预算对话框仅包括金额、北京时间重置说明、当前已用和预留、保存与取消。输入以十进制金额校验，持久化用整数 micro-CNY，禁止浮点累计。原上限未读取成功时不可覆盖保存，不预填人为猜测的默认预算。

- 上调：提交前显示“每日上限从 ¥A 调整为 ¥B”；服务端检查允许的部署／授权边界并返回实际生效版本，不能借页面编辑突破独立费用授权。
- 下调：允许小于今日已用加预留；原费用与预留不回退，保存后停止超出新限额的新预留，进行中调用正常结算。
- 设为 0：表示暂停新增付费调用，不等同于关闭访客入口；首页必须解释因预算暂停。零成本本地操作不因此停止。
- 并发修改：冲突时保留输入并呈现最新版本，让用户重新保存；不静默覆盖。
- 达限：如果仍处于请求开放状态，次日仅在所有准入条件有效时恢复；用户主动关闭的服务绝不因换日自动开放。

“优先保障问答”的具体调度提案：已排队的问答优先于新同步批次；同步分成可中断的小批，在每批预留前给下一次问答保留一笔按当前模型上限估算的安全额度。该规则无需用户设置固定比例，也不保证未来无限问答；预算本身不足一次问答时明确提示。试问同样不能抢占已经预留的访客调用。此调度阈值需在实施规格中通过成本与饥饿场景验证。

总预算必须由一个原子预留权威执行，判定为 `已结算 + 已预留 + 本次预估 <= 每日总上限`。改造前跨库相加只是报表，不能阻止并发超支。当时建议在 API 所有的预算模块中统一预留身份，API 与 Worker 都遵循同一权威；三类账本保留分类记录，不再各自独立批准同一份剩余额度。

存储位置、迁移和跨库恢复属于实施前架构决策：必须保持 Worker 不直接打开 runtime 的边界；明确先预留后调用、幂等结算、未知调用保守占用、进程崩溃补偿、数据库恢复不刷新日预算。不能只把旧三个日上限加在一起自动授权为新上限，也不能把只读汇总先上线冒充预算控制。

## 7. 内容同步与异常处理

发布／更新后使用现有公开事实投影与 outbox 增量处理；“自动同步”并不意味着每次发布全量重建。自动化仍依赖 Worker 在运行，需将 Worker 不可用解释成“内容同步已暂停”，而不是长期停在“同步中”。

“查看内容”显示内容标题、类型、当前同步状态、最近时间，使用有界分页；失败行显示原因与操作。后台需补齐安全的标题与公开修订对齐信息。继续遵守现有语料范围，About 专属文案和草稿不会因为页面重设计自动加入知识库。

| 可观测问题 | 用户看到的解释 | 对应操作 |
| --- | --- | --- |
| 可以安全重试的索引失败 | 部分内容尚未更新到助手，回答可能缺少这些内容 | 重试此内容同步；成功后显示处理中，完成后更新状态 |
| 预算等待 | 为保留问答额度，内容同步暂缓 | 修改预算；查看待同步内容；不要显示无效重试按钮 |
| Worker 不运行／观察过期 | 内容同步暂停／状态待确认 | 查看恢复步骤或刷新；没有服务管理能力时不画假启动按钮 |
| 供应商请求结果未知 | 本次调用结果待核实，重复提交可能再次计费 | 查看诊断；禁止普通自动重试 |
| 资格或配置失效 | 当前运行条件需要重新验证 | 显示具体检查步骤；不伪造页面一键修复能力 |
| 没有足够回答依据 | 助手未找到足够公开内容来回答 | 查看知识同步；调整问题后手动再问 |

重试这种可恢复操作不重复弹确认框，通过原位状态、版本和幂等键防重复；全量重建、切换、提高预算、对外开放等有费用或服务影响的操作使用一次明确影响确认。后台不得自动重放失败的付费 mutation。

内容撤回／删除的失效传播优先于新增内容同步，并且不应等待付费 Embedding 预算。不得因“优先保障问答”继续向用户返回已撤回来源。

## 8. 高级维护

按“运行诊断”“重建知识索引”组织，默认折叠服务提供方、索引代次、资格绑定、Worker 身份等原始信息。保留观察时间、未知及过期状态，敏感配置不出现在页面。

重建流程展示为：确认影响 → 排队／同步中／等待预算 → 已准备好 → 停用并应用新索引 → 检查运行条件 → 管理员再次开放。用户无需理解 generation，但切换停用与资格复验仍必须发生。等待期间显示确切原因，不伪造百分比。

只在操作非终态且页面可见时轮询；离开、隐藏或完成时停止。保留“紧急停止全部问答”，解释与首页关闭对外问答的区别及已发送调用可能计费。

## 9. 视觉与可访问性约束

沿用现有写作台侧栏、字体和主题变量；浅色为白底蓝色重点，深色为深灰底黄绿色重点。主内容宽度建议上限 1040px，桌面内边距 32px、手机 20px；标题 28–32px、正文 14–16px，状态主文案 24px。以上为布局提案，需实际截图核对后微调。

不新增装饰渐变、仪表盘大数字墙和服务徽章矩阵。使用空间、对齐、轻分隔组织信息，危险操作不占正常状态的主视觉。

手机按状态、待处理、费用、知识顺序单列；预算对话框适配窄屏，试问输入始终可达且不遮挡引用。支持 320px 宽及短视口，无整页横滚。操作触控目标至少 44px；页签支持键盘；对话框管理焦点、Escape 与返回触发点；状态不只依赖颜色；发送进度使用适度 live region，不逐 token 打断读屏。

## 10. 实施分解与验收设计

方案讨论阶段未修改运行代码、调用真实模型或调整真实预算与公开开关。以下保留当时的实施顺序及验收目标；后续实现见文末第二版实施记录，不能把第一阶段或静态原型视为完整交付。

| 阶段 | 交付与依赖 | 主要检查 |
| --- | --- | --- |
| A 契约与风险设计 | SDD spec；统一预算权威与迁移／恢复决策；管理员执行范围；公开可用性投影 | 路由、认证、费用、停用与恢复语义无冲突 |
| B 管理基础能力 | 总预算设置／原子预留；独立管理员试问；统一对外控制 | 匿名拒绝、CSRF、并发预算、重启／换日、停用迟到结果 |
| C 页面交互 | 概览、试问、局部详情、高级维护；严格响应解析 | 成功／阻塞／过期／空状态；动作反馈与真实后端对应 |
| D 同步闭环与验证 | 标题／修订状态聚合；优先调度；自动同步反馈 | 发布更新、撤回删除、Worker 暂停、预算等待、恢复重试 |

至少验证：

1. 公开关闭时后台可完成带真实验证引用的试问，匿名无法访问管理试问，公开开关保持关闭。
2. 开放条件不足时解释原因且不宣称成功；关闭后新公开请求被拒，旧页面入口在约定窗口内消失。
3. 访客、试问、索引并发时同一总预算不能被重复分配；未知结果不释放成可重用余额。
4. 调低／提高预算、并发保存、北京时间跨日、崩溃重启和恢复数据不重置或漏算占用。
5. 发布更新自动同步；预算不足时新增批次延后；撤回删除仍及时阻止旧来源被返回。
6. 失败和过期不冒充健康；无可执行修复时不显示会成功的假按钮；试问错误不被转成假答案。
7. 试问来源片段只返回当前允许公开内容；清除、停止、超时及迟到响应遵守会话范围与正文保护。
8. 全量重建和索引切换保留预算、停用、复验和再次开放步骤；重复提交不产生重复命令。
9. 双主题、窄屏、短视口、键盘、焦点与屏幕阅读器可完成主要流程。

## 10. 第二版实施记录

真实入口为 `/admin/assistant`。概览／试问通过 `view` 切换，高级维护为次级入口。概览为纵向操作行，沿用项目字体、浅色蓝与暗色青柠主题；不再显示演示金额或设计预览控件。

新增 `/admin/assistant/management`、`/budget`、`/sync`、`/trial/sessions`、`/trial/session`、`/trial/questions`、`/trial/resume` 与 `/emergency-stop`。只读接口不探测外部服务；失败保留上次快照并撤销正常状态结论。同步任务分页展示公开标题和是否对应当前修订，历史成功明确标注为历史任务，不声称收录篇数。

管理员会话绑定登录会话哈希，独立 Cookie 与服务器生成的 session 命名空间。共用原问答图、共享租约、资格校验、短期保留和引用验证。普通关闭只提升公开 epoch；全局停止、故障阻断与索引切换提升管理员 epoch。切换后必须重新验证，再手动恢复试问。引用展开包含经过最终公开修订复核的片段和安全站内链接。

总预算存于 content 库的 `assistant_budget_policy` 和 `assistant_budget_reservations`，使用整数 micro-CNY。部署总上限保守取既有三个授权分类上限的最大值，而非相加；没有授权时为 0。旧分类账本仍执行各自授权上限。每日总预算可从 0 调整到这个上限；调高会唤醒因预算等待的同步任务，未知调用不能借此重发。

API 先在共同权威提交全部问答尝试的预留，再提交 runtime 准入；runtime 结算提交后复制单调结算收据。崩溃孤儿预留保持占用至原北京时间日期结束，不因查不到 runtime 记录而退回。恢复过的 runtime 不可重发已在共同权威结算的尝试。Worker 在 content 写事务内预留、在供应商调用前提交，结算与原分类账本同事务；不打开 runtime。备份包含两个预算表，恢复将 Worker 与 API 的新增付费调用锁定到次日。

同步每批预留需额外留出一次按当前输入／输出上限估算的问答费用；并发问答在准入时先预留，因此已排队问答的额度不会被同步占用。已发出的调用无法抢占。零成本调用、撤回与删除不受新增付费预算影响。

公开布局消费无诊断的 `/assistant/availability`。活动页请求完成后每 25 秒读取一次，单次超时 5 秒；导航与重新可见时刷新。读取失败隐藏入口，API 准入立即执行运行开关和费用限制。后台“停止接收”停止浏览器接收，明确提示后台调用仍可能继续；需刷新结果确认状态，清空试问才撤销整个短会话。
