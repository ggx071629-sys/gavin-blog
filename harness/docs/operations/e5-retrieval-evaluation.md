# E5 本机检索评估

本文保存 2026-09-06 阶段 D 的方法与测量快照；下文的待办和配置推算均属于该阶段时点。后续真实 Chat 已完成本机联调，见 [阶段 F 交接](local-real-qa.md)；较小资源环境另见 [2 CPU／4 GiB 容器复测](../../../plan-build/capacity-tests/2c4g-retest-concurrency-rebuild.md)。这些记录都不替代生产目标资格。

本工具推进 [阶段 D 归档](../../../plan-build/local-qa/archive/stage-d.md)。题目及 gold 由 AI 起草，管理员已于 2026-09-06 在当前任务明确确认“人工审核通过”，审核绑定见下文。按同日后续指示完成本机完整进程组测量与容量推算，结果见文末；阶段 D 已完成，可以进入 Chat 人工配置，不再要求服务器共驻验收。

## 运行

先按 [API 本机 E5 说明](../../../apps/api/README.md) 启动固定模型服务与 Qdrant，准备忽略配置 `.env.e5`。以下命令从 `apps/api/` 执行；Windows 使用 `.venv/Scripts/python.exe`，POSIX 使用 `.venv/bin/python`。

```powershell
# 不连接服务：校验题集，生成完整原文和逐题标注复核表
.venv/Scripts/python.exe -m app.local_embedding.evaluation --review-only --output data/e5-review-new

# 真实 E5 + Qdrant + 发布 API + Worker + API owner finalize
.venv/Scripts/python.exe -m app.local_embedding.evaluation --env-file .env.e5 --output data/e5-evaluation-new
```

输出目录必须不存在，拒绝覆盖已有运行。每次自动生成两个不同 Qdrant collection 前缀；每种目标语言分别创建 SQLite 内容库、runtime 和媒体目录。通过现有登录/CSRF、文章发布与 Profile API 写入虚构语料，Worker 重建后受控 finalize，并读取 gate 确认 disabled 且无 pending switch。原 `.env.e5` 内容库和真实用户 Profile 均不写入。不会启动在线助手或调用 Chat。

默认题集为 [e5-bilingual-v1.json](../../../apps/api/evaluation/e5-bilingual-v1.json)：每种目标语言 20 篇文章（10 篇相关、10 篇相近干扰）及 1 个虚构 Profile。Profile 必须显式声明，避免默认中文资料混入英文语料；来源按类型与 ID 联合映射。两份语料分开评估，避免同一语料内的等价翻译造成多相关性歧义。共 40 条正向题（四方向各 10 条）及无证据 2 条、术语/代码/混排/超长各 1 条。`--dataset` 可指定同结构题集；此版本只接受明确待复核的草稿状态，不能通过改状态字串伪造人工通过。

## 结果口径

- `review.md`：全部语料、问题、gold 原文、前五名切片与公开路径/版本、逐题复核空栏。
- `results.json`：详细逐题结果，保存在忽略目录。
- `summary.json`：紧凑统计，绑定题集 SHA-256、评估代码 SHA-256、模型/pipeline、两份 generation/collection 及切片/向量集合一致性。
- `failure.json`：未完成测量时明确失败，只包含异常类型，避免泄露供应商配置。已有失败运行保留，重试用新目录。

Recall@5 以检索器返回的前五个 **chunk** 为范围，按相关 **文档集合** 去重：命中的 gold 文档数 / 全部 gold 文档数，再按问题取宏平均。当前每题一个 gold，因此数值等同文档命中率；统计函数支持多个 gold。只将路径和当前公开版本一致的结果计入召回。证据命中另要求 gold 原文完整出现在该文档的返回切片里。向量相似度不作为准确率。

`run_valid` 只表明测量完成、引用有效、没有意外降级；`draft_recall_target_met` 另检查草稿正向集整体 Recall ≥ 0.85。它们都不代表每个边界问题回答正确。无证据问题的 Recall 为 null，近邻只计为 `unsupported_neighbors`；本工具不测 Chat 拒答。超长用例直接测试检索层（可超出公开问答接口输入上限），保留全文并跳过 dense，单独报告关键词降级和证据命中，不混入 40 题正向分数。服务不可用、模型/数据漂移、引用无效、缺失结果或意外降级不会输出有效成功；退出码 1 表示运行无效或草稿 Recall 未达标，0 也不表示阶段 D 通过。

## 本机结果与下一步

2026-09-06，修正评估器默认 Profile 漏登记后，固定题集真实测得整体 Recall@5 与证据命中均为 0.975：中→中、英→英、中→英各 1.0，英→中 0.9。唯一正向漏召回为 `en-zh-queue`（英文询问云雀查询优先级及抢占）；保留失败题，不改题或调参追分。术语、代码、混排命中；6022 tokens 长文本按预期降级但证据命中为 0。两条无证据问题各返回五个近邻，未作为正确答案。完整摘要见 [本机评估 manifest](../../verification/evidence/20260906-e5-retrieval-evaluation.benchmark.json)。

这是规模很小、内容较短、题目与证据共同起草的合成语料结果，存在明显乐观偏差。当前真实快照仅三篇主要中文文章及 Profile，尚不足以验证真实访客的四方向表现。人工审核确认不改变这一覆盖限制。修改题集后需要重新审核与测量，不沿用旧确认或分数。后续在本机运行 Nuxt/API/Worker/Qdrant/模型进程组，覆盖冷启动、稳态和查询与重建重叠，记录资源并按 [阶段 D 测量方法归档](../../../plan-build/local-qa/archive/stage-d.md#method) 推算配置；报告区分本机实测、规划余量和跨平台不确定性。完成后即可继续 Chat 人工配置，无需先准备服务器。

## 本机资源测量入口

从根目录执行 `npm run build:web`，然后在 `apps/api/` 执行：

```powershell
.venv/Scripts/python.exe -m app.local_embedding.capacity --output data/e5-capacity-new
```

当前 collector 支持 Windows，需要可读取进程和 CIM 性能计数器的权限。输入仍用忽略配置 `.env.e5`；`--port-base` 默认为 32400，依次分配 Web/API/模型/Qdrant HTTP/gRPC 五个端口，端口占用立即失败。只允许不存在的输出目录。所需固定 Qdrant 二进制及独立模型环境与前文一致。

命令复制隔离配置，模型只建立经哈希验证的文件硬链接供新 owner 读取，不覆盖原制品；创建独立内容库、runtime、Qdrant 数据目录、随机凭据和新索引。默认将原题集的 40 篇文章正文分节重复 24 次，另加一个显式 Profile，作为容量负载，不改变已审核题集及质量结论。Nuxt 使用构建后的 Node 入口；API 使用显式 development-only 测量适配器，在 API 进程内调用真实 E5 和检索器。`GET /__capacity/query` 必须携带本轮随机 Bearer 凭据，不进入内容写锁；普通 API 应用不会注册这些测量路径。Chat、会话、SSE/checkpoint 路径未启用，须在阶段 F 补测其增量。

采样器每秒枚举本轮根进程及其子进程，按 PID + 启动时间识别，记录累计 CPU 秒、工作集和私有分配；统计使用实际时间差。分别记录冷启动、稳态 30 次、505 tokens 附近输入 10 次、重建窗口 45 次、限制所有受测进程使用逻辑处理器掩码 3 后的 30 次查询。普通查询名义间隔一秒，每轮另请求 Nuxt SSR 首页和经 Web 代理的公开文章列表；这是闭环、单查询并发负载，不是最大吞吐测试。队列每 250 ms 观察一次；未测到队列采样不能当作零排队。

“冷启动”只指新进程启动，不清空操作系统文件缓存。亲和性掩码 3 只代表本机两个逻辑处理器，不等于两个物理核或另一款云 CPU。背景进程工作集/私有分配、整机 CPU、可用内存及页面读入/写出另列，不能把全机换页归因于本应用。工作集含共享和私有驻留页，私有分配与物理驻留不是相同口径；硬缺页也可能来自映射文件读取，不能直接当作 swap 抖动。参见 [Microsoft 工作集说明](https://learn.microsoft.com/en-us/windows/win32/memory/working-set) 和 [PrivateMemorySize64](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.privatememorysize64)。

`samples.jsonl`、`loads.json`、`queue.json`、各进程日志、含秘密的 `config.json` 仅留忽略目录。`summary.json` 绑定工具代码/脚本、查询、语料、模型/pipeline、generation 和 Nuxt 入口摘要；代码中途变化、缺场景/角色、请求错误、重叠不足或清理失败不会认可为有效运行。冷启动采样至少五点；采样间隔和 collector 开销单独报告。失败诊断仅保存在本机，不提交原始日志。

运行结束仅停止本轮新建进程树，保留数据以便核查，既有开发服务不重启。测试会创建两个 generation 和一份实际索引快照、内容快照。磁盘按当前虚拟环境、解释器、Node、Nuxt 产物和模型等文件的逻辑大小计数，硬链接模型按一套可部署制品计；不将硬链接节省误算成模型不占磁盘。估算另外加规划余量与日志预算，OS 磁盘、未来媒体和保留策略单列。

## 2026-09-06 最终容量报告

证据：[本机容量 manifest](../../verification/evidence/20260906-local-capacity-measurement.benchmark.json)。原始运行目录为 `apps/api/data/e5-capacity-20260906-final/`。Windows 11、Ryzen 7 5800H（8 物理核/16 逻辑核）、约 13.86 GiB 系统可见内存；模型仍为固定 E5 FP32。41 个测试来源、每代 1,001 个切片，新旧两代同时保留。阶段 D 仅证明下面的受控本机负载，未调用 Chat。

| 场景 | 查询数/实际 tokens | Embedding p95 | 检索 p95（含 Embedding） |
| --- | --- | --- | --- |
| 稳态 | 30 / 33–53 | 52 ms | 99 ms |
| 近上限 | 10 / 505 | 398 ms | 441 ms |
| 查询与重建重叠 | 45 / 33–53 | 104 ms | 141 ms |
| 限制两个逻辑处理器后稳态 | 30 / 33–53 | 47 ms | 59 ms |

115 次请求均成功，重建窗口 45/45 次确认处于重建期间，观察到队列最多等待 1 项。普通查询位于计划的 32–128 tokens 范围内，但本次实际只覆盖 33–53；长输入另按 505 tokens 测量。服务组就绪约 13.6 秒，连同首次建索引约 78.2 秒；二次重建观察窗口约 59.9 秒。CPU 亲和性实验只覆盖预热后稳态，不声称验证了受限 CPU 下的冷启动或重建耗时。

| 角色（含子进程） | 稳态工作集样本中位数 MiB | 全程采样工作集峰值 MiB | 全程采样私有分配峰值 MiB |
| --- | --- | --- | --- |
| E5 模型 | 981.9 | 996.6 | 2671.4 |
| API | 471.4 | 473.5 | 935.2 |
| Worker | 450.1 | 450.7 | 927.8 |
| Qdrant | 46.2 | 152.3 | 33.7 |
| Nuxt | 90.4 | 150.9 | 126.6 |

稳态窗口共 25 个资源样本，进程组工作集合计的样本中位数约 **1.99 GiB**。各行峰值可能发生在不同时刻，不能相加作为同步峰值；工作集包含共享页，进程间求和可能重复计数。以上是本轮运行时采样结果，测量进程已停止，原有开发服务未停止。

同步进程组工作集峰值约 **2.13 GiB**，同步私有分配峰值约 **4.55 GiB**；各角色私有峰值之和约 **4.58 GiB**。后者不是实际物理驻留量，而是本方案选择的保守内存基线。加 30%（约 1.38 GiB）余量，再另列 0.75–1.5 GiB OS/缓存预算，向上取整得到 **7–8 GiB 内存规划区间**。阶段 D 当时以 **8 GiB** 作为保守规划参考；跨系统库映射、共享页和缓存存在重复或差异，不能据此声称 4 GiB 已经验证可用。

CPU 热态重建窗口的平均需求约 1.06 个本机逻辑核，p95 约 1.19；按 60% 目标占用计算 `ceil(1.19 / 0.6) = 2`，即 **2 个同档逻辑核的热态预算参考**。本次不限核冷启动观察到约 2.03 核短时占用。它不是任意云 vCPU 的等价保证，也不证明更高请求率下的容量；阶段 F 的真实 Chat 路径仍需补测。

磁盘实测逻辑文件合计约 **7.22 GiB**：推理虚拟环境约 3.28 GiB，模型约 0.46 GiB，双代 Qdrant 约 1.85 GiB，索引快照约 0.92 GiB，其余为 API 环境、解释器、Node、Web 产物及数据库。Qdrant 当前配置包含大量 32 MiB 预分配文件，不能按“每个向量的字节数”推算总体磁盘，也不能将该固定开销线性乘以切片数。加 30% 与 2 GiB 日志预留后，应用侧初始空间预算约 **12 GiB**；操作系统磁盘、未来媒体、额外备份/索引保留另算，未作购买实例建议。

采样共 221 点，主要场景采样间隔 p95 约 1.05–1.10 秒，但稳态有一次约 **6.11 秒**的 CIM 停顿；瞬时峰值可能漏采，余量不等于对此误差的证明。背景进程工作集合计约 7.3–8.0 GiB，单列而未作为应用基线；整机可用内存最低约 2307 MiB。观察到两次不连续的系统页面写出样本（初始化 1416 页/秒、受限稳态 108 页/秒），各核心场景 p95 为 0；不能称为完全无换页，也不能将其直接归因于本应用。受测进程没有异常退出，实验结束全部清理；这是短时测量，不是长期耐久或内存限额验证。

结合已确认的人工题集审核和 Recall@5 0.975，当前本机阶段 D 完成。当时管理员查看内存结果后要求“这个先跳过吧，继续推进chat”，因此跳过本机 2 核 / 4 GB 虚拟机验证，恢复阶段 E。阶段 D 结束时待确定供应商、模型、Base URL、测试预算及每日预算；凭据仅在后端私密配置，确认后执行兼容性探测并在后续联调补测完整链路资源。跳过实验不构成 2 核 / 4 GB 容量验收。
