# Context

桌面搜索页当前只在暗色主题下使用居中、窄宽度、带边框和内边距的卡片容器；浅色主题仍使用接近全宽的开放布局。同一路由切换主题时不仅颜色变化，内容宽度、定位和容器层级也发生明显跳变。该差异来自 `@media (min-width: 1024px)` 内仅以 `.dark` 为前缀的搜索页布局规则。

# Goal

让浅色主题在桌面视口复用暗色主题的搜索页结构：外层居中、内容限制为 `max-w-4xl`，面板具备边框、内边距、语义表面背景和主题阴影；颜色、圆角和阴影值继续由各主题的现有语义令牌决定。

# Non-goals

- 不修改搜索请求、结果、分页、SEO 或键盘交互。
- 不改变小于 `1024px` 的现有响应式布局。
- 不修改全局颜色、圆角、阴影或排版令牌。
- 不调整搜索页以外的公开页面或管理后台。
- 不要求浅色与暗色使用相同的原始色值。

# Acceptance criteria

1. 在宽度至少 `1024px` 的视口中，浅色与暗色搜索页的 stage 都使用水平、垂直居中的 flex 布局。
2. 两种主题的搜索面板都使用相同的最大宽度、水平定位、边框宽度和 `32px` 内边距，切换主题不再改变卡片的主要几何结构。
3. 面板背景、边框、圆角和阴影继续引用现有 `--ee-*` 语义令牌，不新增 raw palette 值。
4. 小于 `1024px` 时不应用桌面卡片化规则，现有移动布局保持不变。
5. 自动化 E2E 覆盖桌面双主题的布局一致性，并确认移动视口没有横向溢出。

# Risks

- 将暗色限定规则改为双主题共享规则可能提高浅色页面视觉密度，需要通过实际渲染确认内容没有拥挤或溢出。
- 直接断言颜色会把主题差异误判为失败；测试只比较结构属性，并单独确认两种主题状态确实生效。
- 当前工作区存在其他进行中的样式与公开体验测试修改，本任务必须使用独立测试文件并避免覆盖无关差异。

# Verification plan

- 先新增搜索页双主题布局 E2E，并在现有实现上运行以证明浅色布局断言失败。
- 将桌面搜索页卡片化规则从暗色限定改为双主题共享，继续使用现有语义令牌。
- 运行目标 E2E，验证桌面双主题几何结构一致且移动端无横向溢出。
- 运行 Web 单元测试、类型检查与生产构建，检查无跨页面回归。
- 运行 `python -m tools.harness verify 20260809-sync-light-search-layout` 并记录紧凑 evidence。
