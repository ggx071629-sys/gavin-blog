# Context

媒体目前支持选择、拖放、粘贴与外链登记，但操作集中在上传组件并默认加载资产列表。媒体没有删除、恢复、搜索或精确去重，直接编辑体验和长期管理都会随资产增长退化。

# Goal

让 Markdown 编辑器成为主要图片导入入口，并建立不破坏历史公开链接的媒体软删除、恢复、精确去重和有界管理能力。

# Non-goals

- 不物理删除媒体文件，不释放软删除资产的存储空间。
- 不自动下载外部图片，不做相似图片识别。
- 不建立完整媒体引用图、文件夹或标签系统。

# Acceptance criteria

- 文章、项目和读书 Markdown 编辑区支持粘贴、拖放和文件选择；上传时在原位置显示占位，成功后替换，失败可局部重试或移除。
- 上传和插入不要求离开编辑器；已有资产按需打开选择，不默认加载完整媒体列表。
- 草稿允许缺失图片 Alt，发布前阻止缺失 Alt 的 Markdown 并定位错误。
- 本地上传按内容摘要精确去重，重复内容复用现有未移除资产 URL。
- 媒体列表支持文件名与 Alt 搜索、本地或外链来源筛选、活跃或已移除状态筛选、最新优先和有界分页。
- 单项与当前页批量软删除可部分成功并可恢复；移除资产不再出现在默认列表和选择器，但原公开 URL 继续可访问。
- 外链仅登记 URL，并明确其可能失效。

# Risks

- 媒体模型与 OpenAPI 变更需要迁移且必须保持现有上传事务补偿边界。
- 编辑器异步上传期间光标移动可能导致插入位置漂移。
- 去重与软删除并发需要数据库唯一性和幂等处理。
- 发布前 Alt 校验必须覆盖三类内容且不误判普通链接。

# Verification plan

- Pytest 覆盖上传去重、媒体筛选、软删除、恢复、批量部分成功与公开 URL 连续可用。
- Alembic 升降级和 OpenAPI 快照同步。
- Vitest 覆盖 Markdown 图片 Alt 校验、占位替换和媒体列表状态。
- Playwright 覆盖编辑器粘贴或文件选择、发布前 Alt 阻断、媒体删除恢复和筛选。
