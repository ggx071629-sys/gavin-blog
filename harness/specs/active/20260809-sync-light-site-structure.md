# Context

全站静态审计与浏览器测量确认，主题差异并非平均分布在每个页面：管理后台绝大多数 `dark:` 声明只切换语义颜色，结构已经一致。实际结构漂移集中在桌面首页网格、公开文章列表卡片和全局形状令牌：浅色首页使用 12 栏主介绍加下一行 8/4 分栏，暗色使用 9/3 侧栏并让个人卡片跨两行；浅色文章列表主动清除卡片背景及三侧边框；浅色圆角为 `0/0`，暗色为 `4/8px`。搜索布局与标题字体已由相邻 verified spec 同步，不应重复实现。

# Goal

以现有暗色主题的 Electric Editorial 结构为全站唯一布局规范，让浅色主题复用相同的首页网格、卡片层级、圆角尺度和阴影几何；浅色继续使用自己的画布、表面、文字、边框、状态色和较低阴影透明度。

# Non-goals

- 不把浅色配色替换为暗色配色，不统一原始色值或 `color-scheme`。
- 不修改页面信息架构、文案、路由、搜索、分页、认证、API 或数据模型。
- 不重新实现已 verified 的搜索布局和标题字体同步任务。
- 不改变移动端内容顺序或强制桌面多栏布局进入移动视口。
- 不删除为语义颜色存在的 `dark:bg-*`、`dark:text-*`、`dark:border-<token>` 等主题声明。

# Acceptance criteria

1. 根主题使用暗色规范的 `--ee-radius: 4px` 与 `--ee-radius-soft: 8px`，暗色不再重复覆盖这两个结构令牌。
2. 浅色浮层阴影与暗色使用相同的 `0 18px 45px` 几何层级，但保留适合浅色背景的较低透明度。
3. 桌面首页浅色与暗色共同使用 9/3 网格：主介绍与最近文章占前 9 栏，个人卡片占后 3 栏并跨两行，首篇文章不再只在浅色跨两列。
4. 桌面文章列表浅色不再清除卡片背景及三侧边框，复用与暗色相同的完整卡片结构和共享圆角。
5. 搜索、文章／项目／读书详情、归档、关于、404、公开列表及管理页面不存在主题专属的间距、网格、显示、尺寸、圆角或边框存在性规则；主题差异仅保留颜色、阴影透明度及其他不改变信息结构的视觉令牌。
6. 自动化守卫覆盖 CSS 结构令牌、主题限定选择器和 Vue `dark:` 结构工具类；浏览器场景覆盖首页、文章列表、搜索与管理登录的桌面双主题结构及移动端无横向溢出。
7. 全量 Web 单测、类型检查、生产构建和现有全站质量矩阵通过，或明确区分并报告与本任务无关的既有失败。

# Risks

- 暗色首页较窄的 9 栏主内容会增加浅色大标题换行概率；标题字体已先行统一，仍需桌面与移动实测。
- 将全局圆角同步为 `4/8px` 会影响公开站和后台所有令牌消费者；需要全站质量矩阵覆盖而不是只看首页。
- 恢复浅色文章卡片完整表面会提高视觉密度；应复用现有语义表面与边框，不能新增 raw palette 值。
- 当前工作树并行包含 signal、字体、搜索与写作台入口等 verified 任务，本任务只能修改共享 CSS 中明确属于本 spec 的片段，并使用独立测试与 evidence 文件。

# Verification plan

- 先新增主题结构静态守卫和首页／列表浏览器结构测试，在现有实现上确认因浅色专属结构而失败。
- 最小修改全局形状令牌、首页桌面网格和浅色文章列表特例，不触碰主题色与业务组件。
- 运行目标 Vitest 与 Playwright，验证红绿过程、桌面结构一致和移动无溢出。
- 运行全量 Web 单测、类型检查、生产构建及现有 Playwright 质量矩阵。
- 生成紧凑 application evidence，并从 `harness/` 运行索引生成与 `python -m tools.harness verify 20260809-sync-light-site-structure`。

# Result

浅色与暗色现共享 `4/8px` 形状尺度、同一浮层阴影几何、桌面首页 9/3 侧栏结构、首篇文章布局和完整文章列表卡片；浅色继续使用自己的颜色与较低阴影透明度。静态主题结构守卫、目标 E2E、67 项 Vitest、类型检查、生产构建及全站质量矩阵均通过；质量矩阵覆盖公开站、管理后台与孵化后台的双主题双视口，并保持 Lighthouse 四项分数不低于 98。
