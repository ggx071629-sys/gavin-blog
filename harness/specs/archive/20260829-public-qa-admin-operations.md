# 20260829-public-qa-admin-operations

Deterministic compressed record. The original active spec remains in Git history.

## Goal

交付 `/admin/assistant` 单管理员运营控制面及其严格 API／数据合同，在不修改部署密钥、模型和价格配置的前提下：以 runtime 内默认关闭、版本化且 generation／readiness 绑定的动态准入 gate 安全启停新问答；用不产生供应商费用的被动事实展示 API 能力、readiness、Qdrant、Worker、索引、breaker 与三类预算；通过持久、幂等且受单 owner fencing 保护的 Worker 命令重试当前公开事实或请求全量重建；以北京时间、整数 micro-CNY 和不含正文的聚合数据可信展示当天用量。

停用必须是可线性化的 kill switch：响应返回后不再创建新 session、新 idempotency turn，也没有新 attempt 能越过 `prepared→sending`；已经先越过 sending 线性点的第三方请求无法撤回，因数据库 CAS 与物理网络调用之间存在 handoff，它仍可能在停用响应后才实际发出或完成，但只能进行不含原文的保守 exactly-once 结算，旧 runner 不能恢复回答、事件、history、checkpoint 或 live publish。启用必须 fail closed，且任何 readiness／配置／active generation 漂移都要求管理员在重新建立有效绑定后显式再启用。

## Acceptance criteria

- AC-1: 项目提供可升级、可回滚的最小控制面 schema。runtime SQLite 新增单例动态准入事实，至少包含请求状态、单调 version、operational epoch、当前 readiness／active-generation 绑定、安全更新时间，以及可空的 `switch_pending` operation ID／target generation／finalize token；fresh provision、runtime 数据丢失、缺行、损坏或无法验证时一律默认关闭。content SQLite 新增持久索引命令、单 Worker owner／heartbeat／fencing 与本阶段所需的脱敏日聚合事实；已有索引任务、generation、pointer 和三类账本仍由各自数据库负责。迁移测试覆盖 fresh、上一版本 upgrade、downgrade→upgrade 与 schema fingerprint，并证明 runtime 控制迁移不修改 pinned `checkpoints`／`writes` 表，Worker 从不打开 runtime SQLite。API 静态 capability 关闭时，管理员概览仍能以只读、partial／unknown 语义加载部署配置与 content 侧事实，不初始化问答 runtime、不连接 Qdrant／模型，任何启用请求都 fail closed。
- AC-2: API 静态开关是 capability ceiling，Web 静态开关只控制 launcher 挂载，runtime 动态 gate 才是新 session、新问题和 provider dispatch 的权威准入。启用必须验证静态 capability、单 API owner、当前未撤销 readiness receipt、配置 fingerprint、active generation、cleanup breaker、restore lock 且不存在 `switch_pending`；每个 admission、`prepared→sending` 和正文 mutation boundary 在授权前复核这些绑定，发现 receipt、配置或 generation 漂移时必须在 runtime 原子落为 blocked／disabled、递增 version／epoch 并 fail closed，只有重新满足条件后的显式启用才能恢复。`switch_pending` 期间所有 enable 一律失败；普通 enable 永远不能清除此 marker，只有 API-owner finalize／recovery 在复核 content pointer 与 operation terminal fact 后才能把它收敛为 disabled。FTS5 可用时，Qdrant／Worker stale 可以作为 degraded warning，而不是伪装成 healthy 或无条件阻止启用。启用要求精确 expected version，重复或 stale enable 返回稳定冲突；安全优先的停用即使 expected version 过期也必须可幂等执行并压过并发 stale enable，每次有效状态变化或 generation 切换 fence 都递增 version／epoch。停用与 admission、sending CAS、stage／terminal、Saver 和 publish 服从同一 runtime gate／epoch 顺序：停用响应后零新 session、零新 idempotency turn，也没有新 attempt 能跨入 sending；先于停用提交 sending 的 attempt 属于不可撤回 in-flight，即使物理 provider 调用在响应后才开始或完成也至多一次、不重试，只允许由无正文 recovery path 按既有 price snapshot exactly-once 结算，不能提交答案、引用、event、history、checkpoint 或 hub delivery；尚未 sending 的 attempt 零调用并 exactly-once 释放预留，disable→enable 不能让旧 runner 复活。既有幂等 replay、GET、DELETE、cleanup、recovery 和费用结算仍可用，概览明确显示 effective 关闭、阻塞原因和派生 draining 数量，且不声称能撤回已发送或已线性化交接给供应商的数据。
- AC-3: `GET /api/v1/admin/assistant` 返回带 `Cache-Control: no-store` 的 API 侧脱敏聚合快照，明确区分 deployment capability、管理员请求状态、effective gate／version、readiness 绑定、cleanup／restore breaker、active generation／allowlisted provider-model-pipeline manifest、Qdrant 最近本地事实、Chat 与 Embedding 最近一次本地记录的 metered outcome、Worker owner／heartbeat、最近成功同步、队列计数、进行中操作和三类预算。readiness/configured 与 provider last-success／last-failure／last-unknown 分开表达，不能把 receipt 当成实时可达；每个可失效组件都包含稳定 status／reason code、`observed_at` 与 freshness／stale 信息，缺失、过期、读失败或时钟异常只能是 unknown／stale／partial，不能显示绿色 healthy。普通概览请求的 Chat call、Embedding call 和 Qdrant live call 均为零，不能泄漏 raw endpoint、key、credential fingerprint、HMAC、数据库／运行路径或 raw exception；`/api/health` 继续只表达进程 liveness，不能被改写成助手综合健康。Nuxt 的 launcher flag 不复制到 API；`/admin/assistant` 页面从自身 public runtime config 读取并标明 Web 观察来源，再与 API snapshot 并列组合，任一侧不能冒充另一侧权威。
- AC-4: Chat、query Embedding 与 index Embedding 三个北京时间日账本都以整数 micro-CNY 在权威事务中执行 `settled + reserved + new_worst_case <= cap`，余额为 `max(0, cap - settled - reserved)`；reserve、sending、settle、release、unknown 和跨日均 exactly-once。顺序 reserve→settle→再次 reserve、恰好等于 cap、超过 1 micro-CNY、并发竞争及北京时间零点都不能超售；供应商回报或保守结算使 settled 超过 cap 时保留真实 overage、打开相应 circuit 并阻止新调用，而不是截平数字。管理页把人民币 2 元明确标为 Chat 新调用的配置估算日 cap，query Embedding 与 index Embedding 使用各自独立、只读 cap；三者都不是供应商账单保证，也不能合并后宣称总支出不超过 2 元。当天 calls、可证实 usage／Token、费用、accepted questions、每个已提交服务端 rate-limit 判定、refusal、degraded、error、安全分类和不含正文的有界 latency 摘要按 BJT、稳定服务端事件身份和 exactly-once 事务统计，未越过 sending 的预留不算 provider call；sending／unknown 或供应商未返回 usage 时 cost 可保守结算，但 Token／usage 必须为 unknown／null，不能由最坏费用倒推。延迟摘要不构成生产性能验收；旧的全生命周期／漏项副本不得冒充今日权威值，无法可靠回填的历史显示 unknown。跨 runtime／content 的展示保留各自 `observed_at`／`copied_at`，content 副本不能参与在线准入。
- AC-5: 管理端提供 `limit=20`、`1..100`，`offset=0`、`0..100000`，按 `created_at DESC, id DESC` 稳定排序且可按 allowlisted 状态筛选的索引任务列表；只返回 task／source 标识、任务类型、目标操作、状态、attempt 次数、allowlisted safe error code 对应的固定服务端文案和时间戳，不返回或直接转发现有 `last_error_summary`、公开正文之外的内容、chunk、向量或 raw provider 信息。手工 retry 只接受 terminal failed，要求 expected state／version 与 `Idempotency-Key`；原失败行保留作审计，服务端重新读取当前公开投影，按当前 revision／pipeline／generation 产生或幂等合并一个新的 upsert／delete／purge 意图。delete／purge 或可证明 provider 未 sending 的失败可安全重试；sending／unknown 永不可重发；已明确 succeeded 但下游结果未持久化时，只有管理员确认后才能创建带 prior-attempt lineage、重新预算且明确可能重复计费的新 operator-authorized attempt，不能静默绕过原 fingerprint 或冒充同一次调用。旧修订、已移入回收站、永久删除或已变私有的内容不能因 retry 被复活；同一 key、双击、延迟响应与并发 outbox 最多形成一个当前意图，stale／不可安全重试返回稳定机器码且 provider call 为零。
- AC-6: 索引 Worker 具有独立于任务活动的 singleton owner、heartbeat、租约续期和单调 fencing token；两个 contender 最多一个 owner，idle 不等于 dead，长 Embedding／Qdrant 调用越过旧 task lease 时不能被第二 Worker 双领或双发。失去 fence 的 Worker 不能提交 task、vector result、generation 或 pointer；prepared attempt 零调用并释放预留，已经 sending／unknown 的 attempt 不重试，只能由当前 owner／recovery 通过独立无正文 path 按既有 price snapshot exactly-once 保守结算。每次外部 Qdrant mutation 前后都复核 owner／task fence 与当前 source revision；rebuild 只写 generation 独立的 staging collection，增量 point identity／payload 与删除 selector 必须同时绑定 generation、source、target revision 和 pipeline，使 stale upsert 或旧 revision delete 无法覆盖／删除新 revision 且不具备检索资格。只有 current owner 在紧邻外部调用前复核 source 仍永久不存在、task fence 仍有效时才可执行 source-wide permanent purge；任何失 fence 的已发生副作用都由 current owner 持久记录 repair 意图并重新投影当前公开事实，不能假装 SQLite fence 可回滚 Qdrant。

  `POST /api/v1/admin/assistant/index/rebuilds` 只以 `Idempotency-Key` 写入 durable command 并返回 `202`／operation ID，HTTP 请求内零 Embedding、零 Qdrant rebuild；同一时刻最多一个非终态 rebuild，所有增量与重建工作通过同一 fenced 单并发调度，且具有按 source revision 持久化的 staging 进度／cursor。全局增量 outbox 仍优先投影当前 active generation 和逻辑 FTS／删除事实，不能因为同一 source 已写 staging 就被标成只对 active 未完成的 succeeded；staging 使用独立进度读取当前公开投影并在 source 变化时标脏／catch-up。index 预算暂不可用时，active 增量保持 pending／degraded 而不被重建截留，恢复后先处理 active，再继续 staging。Worker crash、lease expiry 或 index 预算跨日等待后必须在同一 staging generation 继续，已成功且未变 revision 的 source 不重复 Embedding，已变化的 source 重新进入 catch-up；不能每天从头创建 generation 而永远耗尽 cap。额度不足时以 waiting／deferred 状态停到下一 BJT 日且零额外调用，失败或 abandon 保持旧 active generation／pointer。

  Worker 只把 manifest、source high-water、catch-up、当前公开 revision digest、计数、维度和 Qdrant 结构验证全部通过的新 generation 标为 `ready_to_switch`，不得直接打开 runtime 或 activate pointer。切换验证不得再直接调用云端 Embedding；它复用已计费 staging vector 或固定本地非零等维向量做 Qdrant read probe，额外 provider call count 为零。管理员随后显式调用受 expected operation version 与 `Idempotency-Key` 保护的 finalize mutation；单 API owner 先在 runtime 原子写入绑定 operation／target／token 的 `switch_pending`、关闭 gate 并递增 version／epoch，失败则不切换，所有并发 enable 被 AC-2 阻止。第二步 content `BEGIN IMMEDIATE` 必须同时复核 operation/finalize token、pointer、outbox high-water、当前公开 revision digest 与 staging manifest；ready 后发生任何发布、更新或删除都使操作退回 catch-up，不得切 pointer。通过后才原子切 pointer并写 switched fact，最后由 API owner 复核 pointer／operation 后把 runtime marker 收敛为 disabled；失败／abort 只有在复核 pointer 仍是旧 generation 与 operation terminal fact 后才能清 marker。任一崩溃点最多留下“switch pending、尚未切换”或“switch pending、已切换”的 fail-closed 可恢复状态，绝不能被普通 enable 绕过；finalize 重试负责确定性 reconciliation。切换后保持 disabled，现有 operator readiness 流程为新 generation 签发有效 receipt 后，管理员才可显式 enable。进度、最近成功同步和错误只以安全字段展示。
- AC-7: 控制面使用显式、加法式合同：`GET /api/v1/admin/assistant`、`PATCH /api/v1/admin/assistant/availability`、有界 `GET /api/v1/admin/assistant/index/tasks`、`POST /api/v1/admin/assistant/index/tasks/{task_id}/retry`、`POST /api/v1/admin/assistant/index/rebuilds`、`POST /api/v1/admin/assistant/index/rebuilds/{operation_id}/finalize` 及按 operation ID 查询状态；GET 状态绝不隐式 finalize 或修改业务事实。所有 GET 要求现有 `require_admin`，所有 mutation 要求现有 session CSRF；body／query 严格拒绝未知字段，availability 的 enable 使用精确 version fence，而 disable 按 AC-2 对 stale version 安全优先；retry、rebuild 与 finalize 使用 `Idempotency-Key`，finalize 另要求 expected operation version，GET／mutation／错误均 `no-store`。成功与 `400／401／403／404／409／429／503` 使用稳定 status、严格 schema 和既有 `ErrorEnvelope`，异步命令返回 `202`；错误只由 allowlisted code 映射到长度受限的固定纯文本文案，不直接回传现有 error summary 或 raw exception。OpenAPI、FastAPI response model、Web TypeScript 类型和严格客户端解析同步；浏览器永不直连 Qdrant、Worker 或模型供应商，控制面不能读取秘密／raw endpoint，也不能修改 provider、model、price、Token 或 cap 等部署配置。
