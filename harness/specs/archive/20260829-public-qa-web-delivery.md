# 20260829-public-qa-web-delivery

Deterministic compressed record. The original active spec remains in Git history.

## Goal

在不改变 RAG、LangGraph 图拓扑、费用／限额数值和管理员流程的前提下，先闭合 session tombstone fencing、runner 异常终结与公开 wire 投影，再为 Nuxt 默认公开布局增加独立、默认关闭的 `问 Gavin` 悬浮入口。入口只在显式开启 Web flag 后渲染，首次打开才通过同源代理建立或恢复匿名短会话；面板用现有 Electric Editorial token 呈现完整问题、四段固定进度、服务器验证后的整段答案、编号引用与来源台账，不展示 token 流或半截草稿。

交付应把“聊天机器人”外观改写为本站自己的批注校样／evidence ledger：克制的 4px 形状、细规则线、mono 元标签和明确来源优先级，而不是头像、渐变、发光球、打字圆点或大胶囊。小于 640px 使用可访问的全视口 modal；640px 及以上使用明确打开时聚焦输入、但不 inert 页面或困住焦点的右下非模态面板。所有文案从访客角度说明能力、范围、外发与清理语义，不把 AI 冒充站长本人。

为支持刷新恢复，对外 API 合同只做 additive 变化，内部则执行上述 fence／runner hardening：在现有最多约 15 分钟且可能受 256 KiB cap 提前清理的 terminal body 窗口内返回 completed turn 的问题、答案、引用与来源，正文清理后只返回明确的 `body_available=false` tombstone 元数据；同一只读快照另返回最多一个 active turn 及其固定阶段。已有有效 session 每次 bootstrap 都同步并重新签发同一 session-bound deterministic CSRF，且不刷新配置化 idle TTL。浏览器不持久化原始问题、答案、幂等 key 或 payload；普通断线只在内存仍在时用同 key／同 payload／最后 event ID 有界重连，整页刷新则通过只读 session polling 等待既有 active turn 完成，绝不以新 key 自动重问。

## Acceptance criteria

- AC-1: Web 增加显式解析的 `NUXT_PUBLIC_ASSISTANT_UI_ENABLED`，缺失、空值或非严格 `true` 均为 false；false 时默认布局不渲染 launcher／panel、不创建助手 session、不请求任何助手 API，现有站点也不要求助手配置。true 时 launcher 只按 `route.path` allowlist 出现在 `/`、`/articles`、`/notes/{year}/{month}/{slug}`、`/projects`、`/projects/{slug}`、`/books`、`/books/{year}/{month}/{slug}`、`/archive`、`/about`、`/search`，query／hash 不参与匹配；其他路径、`/admin`、后台 preview、错误布局与 SSR 数据获取均无入口或助手请求。服务端与浏览器仍只支持同源相对 `/api/v1`；在任何助手 bootstrap、GET、POST 或 DELETE 前，客户端都必须把 browser-visible API base 解析并与 `window.location.origin` 精确比较，失败时不建立 session、不发送问题或会话数据，也绝不降级到跨源绝对 URL。launcher shell 保持轻量，panel、SSE parser 与会话逻辑在首次打开前不加载／不运行；不增加外部字体、图片、脚本或网络依赖。
- AC-2: 右下 launcher 使用现有 `--ee-*` 语义 token、手写 SVG、至少 44×44 CSS px 触控区和明确可见的“问 Gavin”身份；面板采用 `ASK / GAVIN`、细规则线、mono 阶段／来源标签和低圆角 evidence ledger，不使用头像、渐变、发光、虚构在线状态或 token 打字动画。`<640px` 为覆盖视口的 `100dvh` modal，处理 safe-area、独立 transcript 滚动和固定输入区；`>=640px` 为约 400–440px 宽、受视口高度约束的右下非模态面板，内容通过滚动完整可达。320、390、639、640、1024、1280 与 1440px 以及深浅主题均无横向溢出、遮死控制或答案／来源 line-clamp；约 500 中文字符目标答案不得被 CSS 或字符串硬截断。
- AC-3: launcher 暴露 `aria-haspopup="dialog"`、`aria-expanded`、`aria-controls` 与准确 accessible name。移动 modal 具有可见标题、`role=dialog`、`aria-modal=true`，打开后焦点进入、背景（含 header、main、footer 与 launcher）inert、页面滚动锁定、Tab 循环；Escape、关闭按钮或 backdrop 关闭后，仅在 launcher 仍挂载时把焦点还给 launcher。来源点击或其他路由变化关闭面板时不恢复旧 launcher，导航完成后把焦点移入新页面 `main`／首个 H1。桌面 panel 同样是由可见标题命名的 `role=dialog`，但不声明 `aria-modal=true`、不 inert 页面或囚禁焦点；用户显式打开时焦点进入 textarea。已打开面板从 `>=640px` 降到移动断点时原子启用 modal/inert/lock，并在焦点原本位于外部时移入 dialog；升到 640px 时清除 trap/inert/lock 且保留合理当前焦点。transcript 使用有名称的 `role=log`；GET hydration 期间显式关闭 live announcement，完成后只播报一次“已恢复 N 轮”，再启用 polite，仅新增阶段／终态进入 live region，失败只触发一次 alert；新消息不抢输入焦点，用户向上阅读时不强制滚底而显示“有新回复”。所有操作触控区至少 44×44px、相邻至少 8px，颜色与焦点满足 WCAG AA，`prefers-reduced-motion` 下移除非必要过渡。现有导航在 `<1280px` 仍是 modal，因此共享唯一 overlay owner 覆盖全部 `<1280px`：打开任一浮层先关闭另一浮层，640–1279px 打开导航可最小化助手但不取消后台 turn；modal handoff 时旧 owner 以 `restoreFocus=false` 原子释放、新 owner 接管 inert／lock 后再聚焦，禁止旧 owner 把焦点抢回 launcher，任何断点变化都不得残留 inert、scroll lock 或双焦点陷阱。
- AC-4: 首次打开前不建立 session；通过 AC-1 同源检查后，同一 browser document 首次打开最多自动执行一次 `POST /api/v1/assistant/sessions` bootstrap，成功后再 `GET /api/v1/assistant/session` 恢复视图，随后最小化／重开不重复 bootstrap；只有 AC-9 明确的用户“重新同步／开始新会话”动作可在同一 document 再次 POST。API 必须先识别有效 session，再只对真正创建的新 session 计入 5 次／10 分钟创建限额；bootstrap 不刷新 idle TTL。已有有效 session 返回同一 session，并在每次 bootstrap 使用服务端 secret 与独立 domain separation 生成同一 session-bound deterministic CSRF token、同步其 hash 且重新签发 Cookie；同一 session 的并发标签页响应因此得到相同 token，响应乱序后浏览器最终 session／CSRF Cookie 对仍对应服务端 hash，不以“偶发 403 后再试”掩盖竞态。CSRF header、Cookie 与已存 hash 的全部验证使用 constant-time compare。每个 mutating request 在发送前立即从当前 `gavin_assistant_csrf` Cookie 读取 header 值，不长期复用可能过期的内存副本；token 只留 Cookie／Vue 内存并由独立 `X-Assistant-CSRF` 使用，不能复用管理员 `gavin_csrf`／`X-CSRF-Token`。网络、403、429、503 不得被误判为“再建一个即可修复”，CSRF 同步不能绕过精确同源、Fetch Metadata 或后续 double-submit；初始化时可创建一次新 session，但问题已被接受后的 question／重连／polling 遇到 401 只允许用户显式重新开始，绝不自动重交问题。欢迎区在首次提问前持续可见地说明：这是 AI；只依据已收录的本站公开内容，不进行联网搜索、不读取站外资料；本次问题、当前短会话最近最多 4 轮问答以及必要公开片段会发送给云端模型；不要粘贴 JD、联系方式、凭据或第三方机密；清除本站短会话不能撤回已发送给模型供应商的数据，也不能改变供应商留存政策。UI 从服务端 `AssistantClientPolicy` 把实际字符上限、session 期限和正文最长保留期格式化给用户，默认值才是 500 字、30 分钟空闲／24 小时绝对期限，问答正文默认最多约 15 分钟且可能因 256 KiB rolling cap 更早清理为最小 tombstone；不能把默认值硬编码成部署事实，也不能把 session 期限误写成正文保留期。三个示例问题只填入 textarea，不自动发送或消耗问答额度。
- AC-5: FastAPI/OpenAPI 与 `apps/web/types/api.ts` 同步 additive 消费合同且不迁移数据库：completed `SessionTurn` 返回 nullable question、answer、typed citations／sources、terminal status/code/message 和 `body_available`；citation/source 的 `n` 保持 Phase 2 decimal string wire type。正文最多保留到 terminal 后约 15 分钟，且可能因 session 256 KiB rolling cap 更早清除；无论年龄，只要已清理就不回填或伪造，而保留 `body_available=false` tombstone 元数据。一次 `control.read` 事务／一致快照取最新 20 条非 preflight-blocked completed turns 后按 `created_at` 升序返回，并同时划分最多一个非 preflight-blocked `active_turn`，避免 terminal 转换瞬间从两边都消失；active view 只含 turn ID、仍可用的 question、created_at 和从该 turn 最新四类 journal stage 得到的 `checking|retrieving|composing|validating|null`，若同一 session 出现多个 accepted／running turn 则 fail closed 为 not ready，不能以任意 `LIMIT 1` 隐藏损坏状态。该 view 不暴露 idempotency HMAC、费用、evidence、checkpoint 或其他内部状态。`SessionCreateResponse` 与 `SessionStatusResponse` 都返回 `AssistantClientPolicy { question_max_chars, session_idle_seconds, session_absolute_seconds, body_retention_seconds }`；值来自已验证配置／既有清理常量，默认 `500/1800/86400/900`，`question_max_chars` 必须在 1–2000 且不超过 request/OpenAPI envelope，其余值必须为正数，策略无效则 fail closed 为 not ready。公开 SSE data 采用严格 allowlist：阶段仅 `{event_id, turn_id, stage}`，refusal／error 仅 `{event_id, turn_id, type, code, message}`，answer 在同一终态字段上增加 `answer/citations/sources`；journal 内部 `idempotent` 必须在出网前剥离，客户端拒绝它和其他未知字段。OpenAPI 通过显式 metadata 声明 questions 的必填 `Idempotency-Key`／`X-Assistant-CSRF`、可选 `Last-Event-ID`，DELETE 的必填 `X-Assistant-CSRF`，以及上述 payload，但运行时继续由手工验证／统一翻译维持 `400 invalid_request`、`403 csrf_failed` 等稳定机器码，不能泄漏为框架默认 422。online runtime 中所有 assistant endpoint 在读取／改变 session 前都执行既有每 IP 30 次／分钟廉价 envelope；GET status 与 DELETE 只计 envelope，不计 session-create／question，也不刷新 idle TTL。bootstrap、questions 与 DELETE 在创建 turn、tombstone 或任何付费副作用前验证精确 Origin 与 production Fetch Metadata；GET status 在 production 要求同源 Fetch Metadata／受信 public host，不能要求浏览器通常不会发送的 GET Origin。DELETE 的 origin／metadata／CSRF 任一失败都必须发生在 tombstone 前。所有 bootstrap/status/delete、SSE 和错误响应（包括 GET status 与 202 revoking）均显式 `Cache-Control: no-store`，Nuxt/Nitro 不缓存或 SSR 序列化 session view；DELETE 的 204 与 202 都必须在实际返回响应上撤销 `gavin_assistant_session` 和 `gavin_assistant_csrf` 两个 Cookie。API 测试证明 preflight-blocked 原文仍不出现在 session view，过期／tombstoned session 不可读取，CSRF 同步不允许跨源读取或绕过后续 double-submit，只有实际新建才消费 session-create 限额。
- AC-6: 专用客户端使用 `fetch` + `ReadableStream` 消费 POST SSE，不使用不支持该请求合同的 `EventSource`，也不复用会缓冲 JSON 的普通 `apiFetch`。每次提问以 `crypto.randomUUID()` 生成一个满足合同的 key，冻结规范 question 与发送时 `route.path`（不含 query、hash、页面正文）；初始发送和每次重连都按 AC-4 临发送时读取当前 CSRF Cookie。所有助手 fetch 设置 `redirect: "error"` 并拒绝 `response.url` origin/path 漂移。questions 的 `200` 成功分支只在 Content-Type essence 精确为 `text/event-stream` 时读取 SSE；非 2xx 分支只接受预期状态、Content-Type essence `application/json`、最多 16 KiB UTF-8 且字段严格为 `ErrorEnvelope { error: { code, message } }` 的一次性错误体，再按 AC-9 的 code 处理，其他状态／类型／超限／畸形体都安全失败且不显示原始 message。不会先因“非 2xx”拒读而丢失同状态下的稳定机器码。同 session 同时仅一个 in-flight，中文 IME composing 时 Enter 不提交，Enter 提交、Shift+Enter 换行，按 Unicode code point 计算并显示 `0–policy.question_max_chars`，默认 500、上限 2000，空白／越界在本地拒绝且服务端仍为权威。textarea 使用 `autocomplete="off"` 且不提供可恢复的表单 `name`；document `pagehide` 与 BFCache `pageshow.persisted` 清空 draft、transcript、key／payload 等原始 Vue 内存，完整 reload／BFCache 返回后只能按 AC-7 只读恢复，不能依赖浏览器表单恢复。纯函数 parser 对每条连接使用 streaming、fatal UTF-8 `TextDecoder`；同一 logical turn 跨初始流与最多两次重连累计最多接收 16 个 event、256 KiB UTF-8，每 event 最多 64 KiB，当前连接未完成 residual buffer 最多 64 KiB，重连不得重置 logical-turn 计数器；超限、非法 UTF-8 或 EOF 残片均失败。它只接受严格公开 allowlist、跨重连单调 SSE id、相等的 data `event_id`、固定同一 `turn_id`、四种阶段和恰好一个 `answer|refusal|error` 终态；内部 `idempotent`、未知 event／字段、重复或倒退 id、非法 JSON、越界 payload、终态后数据或无终态 EOF 都安全失败且不渲染原始内容。
- AC-7: 普通网络断开或同源 Nitro stream 提前结束时，只在原 question payload、idempotency key 与最后已确认 event ID 仍在 Vue 内存时做最多两次有界退避重连，并携带同 key／同 payload／`Last-Event-ID`；绝不生成新 key、静默重问或把关闭 panel 描述为取消 provider。两次 stream 重连仍无终态时转为只读 session 恢复，不再 POST：从 `active_turn` 显示“正在完成上一个问题”，每 3 秒 GET，并按 AC-9 尊重合法 `Retry-After`；从开始 polling 起最多 180 秒后停止自动请求，显示“稍后检查结果”与只触发 GET 的人工刷新入口。该 180 秒只是浏览器自动轮询 horizon，不是对 Embedding、Chat、provider timeout 或 runner 完成时间的承诺。最小化、公开路由切换和主题切换不取消仍在进行的 turn，当前 path 只在下一次新问题发送时更新；整页刷新不在浏览器持久化 payload，同样只用 active-turn polling 等待既有 runner。Nitro 上游只接受服务端固定的 API target，禁用 redirect、拒绝上游 URL／origin 漂移和非 `text/event-stream` 成功响应，并逐段转发状态、`Cache-Control`、`Retry-After` 与禁缓冲 header；它不缓存 session view，也不把阶段缓冲到 terminal。浏览器断开不触发第二次 provider 调用，服务端同 session／同 key／同 payload 的幂等接纳与 replay 由 API 集成测试证明。`active_turn` 只表示 AC-11 下仍可恢复的唯一 live turn；question admission 不得在旧 accepted／running turn 尚未安全收敛时创建第二 active turn，runner 异常、进程重启或 session deadline 都必须落到已有安全终态／tombstone，不能把 quiescent orphan 永久展示为“仍在处理”。
