# 20260828-public-qa-online-core

Deterministic compressed record. The original active spec remains in Git history.

## Goal

在不改变现有公开阅读、全站搜索和管理员流程的前提下，用显式、有限状态的 LangGraph `StateGraph` 编排 LangChain 结构化模型调用与既有 Hybrid Retriever，交付可供后续悬浮气泡消费的匿名公开问答 API。在线路径必须在任何付费调用前完成同源、输入、会话、速率、并发与最坏费用准入；把检索内容视为不可信数据；只返回通过当前公开修订、结构、引用与完整性校验的整段答案；并以短期可删除状态、幂等调用账本和安全聚合指标限制隐私、重复扣费及滥用风险。

实现采用 LangGraph 官方 checkpointer 接口保存短会话图状态。考虑目标服务器资源与极低并发，本阶段允许 `AsyncSqliteSaver` 作为有条件的项目例外，但只允许单 API 进程、独立于内容事实库的本地 assistant runtime SQLite 和显式 owner lease；该 runtime 文件同时承载短期控制账本与 checkpoint，明确不进入长期备份。出现第二个 API 进程、任何非 owner 进程打开 `assistant_runtime`、共享网络文件系统，或初始化、并发、重启恢复、备份隔离、TTL 清理前提不满足时，公开助手必须失败关闭；只访问内容事实库与 Qdrant 的独立索引 Worker 不受 runtime 单进程限制且被禁止打开该文件。该例外不改变官方生产优先使用 Postgres checkpointer 的一般建议。

为保持 active spec 可执行，实现在同一 feature flag 下依次完成三个不可独立开放的内部里程碑：先完成依赖、provider、迁移、checkpoint 与准入账本；再完成 Retriever hydration、StateGraph、结构化回答和公开 API；最后完成攻击／竞态矩阵、OpenAPI、回归与长期文档。只有全部 AC 与 release bundle 通过后才允许进入部署验收，任一中间里程碑都不得打开公开入口。

## Acceptance criteria

- AC-1: API 依赖与 lockfile 显式加入彼此兼容的 `langchain>=1,<2`、`langchain-core>=1,<2`、`langgraph>=1.1,<2`、`langsmith>=0.3,<1`、`langgraph-checkpoint-sqlite` 和 `langchain-openai>=1,<2`，并由 lockfile 固定实际通过测试的完整解析版本；LangSmith 作为直接依赖但原始内容 tracing 仍按 AC-12 默认关闭。首个 provider 边界固定为 OpenAI-compatible Chat Completions／Embeddings，`ChatOpenAI` 显式设置 `use_responses_api=False`、`streaming=False`、`max_retries=0`，Embedding 与底层 SDK/HTTP 同样关闭重试，禁止根据 model name 或 endpoint 隐式切换 Responses API；不得引入 `langchain-community`、Deep Agents、Tavily／联网搜索或其他未使用的 agent/tool 依赖。Chat 工厂返回 LangChain `BaseChatModel`；自有 metered Embedding gateway 实现 `Embeddings` 兼容接口，同时向 Worker／query 路径暴露受各自账本约束的向量与 usage 结果，不能因标准 `embed_query` 只返回向量而丢失费用信息。development/test 使用无网络确定性替身；production 禁止替身、占位 provider/model/version、隐式默认模型和运行时自动安装包。第一阶段 Worker 获得真实 OpenAI-compatible Embedding 实现，但仍是只写内容事实库／Qdrant 的独立进程，绝不打开 `assistant_runtime`；API query runtime 与 indexing runtime、配置、预算及 owner 分离。API 未启用助手时不构造模型、不连接 Qdrant／checkpoint，也不要求任何在线助手环境变量。
- AC-2: 内容事实库通过现有 Alembic 链新增两类不含正文或逐 turn 数据的对象：北京时间日聚合指标，以及仅由独立索引 Worker 所有、与既有 outbox/generation 同库的 index-embedding 固定点预算／reservation／attempt 账本；后者可以保存任务／generation 标识、请求指纹、价格快照、usage、费用和状态，但不得保存切片正文、向量、provider raw response 或匿名会话标识。fresh、upgrade 和 downgrade → upgrade 均可验证且旧迁移保持不变。匿名 session、turn／幂等键、Chat 与 query-embedding 费用账本、online provider attempt、readiness receipt、速率事件、并发 lease、每 turn 有界 SSE event journal 与 LangGraph saver 表全部位于独立 `assistant_runtime` SQLite；该文件只有单个 API 进程持有 owner lease，索引 Worker 绝不打开它。应用自有 runtime 表使用独立 Alembic migration chain 及独立 version table，只管理 allowlist control 表，绝不得 autogenerate、drop、rename 或迁移 Saver 固定表，Saver provisioning 也不得触碰 control 表。Saver 在 API lifespan 内独占自己的 `aiosqlite.Connection`，control 与 Alembic 使用另外的连接／engine，禁止借用 Saver 内部连接或假设同文件的 control 与 checkpoint 能跨连接原子提交。每条 Saver／control 连接建立时均设置并验证 `busy_timeout`、`secure_delete=ON`、`synchronous=FULL` 与 WAL，control 连接还须 `foreign_keys=ON`。显式 provisioning 命令必须取得与 API owner 竞争的同一个跨进程排他 mutex／OS file lock，并在无 active runner 且 Saver connection 已关闭时贯穿固定顺序的 runtime Alembic、受支持的 Saver setup、schema fingerprint／receipt 生成与复核；它不能先检查“当前无 lease”再无锁执行，也不能与 API lifespan 并存。API startup 取得同一 owner lock 后，必须先用独立只读连接严格验证已 provision 的 schema/version/fingerprint，缺失、损坏或不匹配即失败关闭，绝不实际创建、迁移、修复或自动重建 schema；验证成功后才允许 pinned `AsyncSqliteSaver` 实例执行其官方首次使用必需的幂等 `setup()`，并断言前后 schema version、表／索引 allowlist 与 fingerprint 完全不变，任何实际 schema change 都使启动失败。control 写事务必须短且不得跨 provider 请求、`graph.astream`／Saver API、节点返回或任何会触发 sync checkpoint 的 `await`；admission／budget／lease 可用短 `BEGIN IMMEDIATE`，仅在任何付费副作用前对 `SQLITE_BUSY` 做有界重试。runtime control 表中的 turn、online attempt、Chat/query 费用账本与 terminal event 是在线付费副作用、幂等恢复和客户端交付的唯一事实源：cookie／CSRF 原值只发给客户端，库中只存不可逆 HMAC/hash；provider 返回后必须先在一个短 runtime 事务中保存 TTL 内可复用的 allowlist parsed Chat result 或 query vector、finish reason、usage 与 attempt 状态，再立即丢弃 raw provider response，之后才允许 LangGraph 节点返回。checkpoint 只是同一文件中可对账、可丢弃的单个 in-flight turn 编排恢复状态；每个已接受 turn 创建一个服务端随机内部 `thread_id`，同幂等 turn 的恢复复用它，多轮历史从 runtime control 表有界加载，新 turn 不复用旧 thread，terminal control 事务提交且 runner quiescent 后调用 `adelete_thread()`，因此 checkpoint 不承担跨 turn 记忆且不能无限增长。任一 control／checkpoint 写入窗口崩溃后，都以带 fencing token 的 control attempt/terminal 状态决定复用已完成结果、恢复未开始节点或把 `sending`／未知调用安全终止，绝不凭 checkpoint 自动重复付费副作用；索引调用则只服从内容库中的 index attempt 事实源。
- AC-3: `GAVIN_ASSISTANT_ONLINE_ENABLED` 默认 false；关闭时现有 API、内容迁移、OpenAPI 生成和测试在没有模型、Qdrant、runtime SQLite 及助手密钥时保持可用，助手业务路由返回稳定且不泄露配置的 unavailable 语义。production 启用前必须显式提供 Chat 与 Embedding 的 provider、model、model version、HTTPS endpoint、API key、维度／上下文及输入输出 token 上限、最多 120 秒 provider timeout 与最多 30 秒 runner cleanup grace、finish-reason／usage 能力、以人民币归一化的价格、北京时间自然日且均无隐式默认值的 query-embedding／index-embedding 两个预算池、Qdrant 配置、规范公开站点 origin、受信代理范围、彼此独立的 IP／readiness HMAC secret、runtime 路径和单进程声明。实现须交付不会在启动／普通 health check 中隐式调用云端的显式 readiness 命令；自动化只用替身验证命令、receipt 及配置／能力失败时 fail closed，真实 structured-output、usage、finish reason、Embedding 维度、活动 generation compatibility manifest 与 Qdrant 探针由部署者在启用前人工运行并承担单独费用。成功命令在 runtime control 表写入不含 API Key 的 readiness receipt，绑定应用 release／assistant policy version、provider/model/version、Chat／Embedding／Qdrant 规范 endpoint、结构化 schema hash、token/timeout、价格与预算快照、Embedding identity/dimension、活动 generation 的 collection／distance／pipeline compatibility fingerprint、探针时间，以及分别用 readiness secret 对实际 Chat／Embedding／Qdrant credential 计算的 fingerprint，并对完整 receipt 再做 HMAC 防篡改；在线路径在任何 Chat 前重算并恒定时间验证，任一绑定值、credential、活动 generation compatibility 或显式撤销变化立即失效并要求重跑。真实探针本身不是本 spec 的自动化通过证据，但缺失／撤销／不匹配 receipt、owner lease 或活动索引时运行时必须失败关闭；Embedding／Qdrant 查询故障可以进入明确的 FTS-only 降级，但不得以测试向量或旧 generation 冒充正常。
- AC-4: 新增并在 OpenAPI 中完整声明同源 `fetch` 客户端使用的匿名 API：`POST /api/v1/assistant/sessions` 仅在缺失／过期时创建短会话，已有有效会话幂等返回，并设置 Secure（production）、HttpOnly、SameSite=Lax 的专用 opaque session cookie 与可回送的 session-bound CSRF；`GET /api/v1/assistant/session` 有界返回当前会话状态与已完成 turn；`DELETE /api/v1/assistant/session` 立即 tombstone session 并撤销浏览器 cookie／读取权，只有不存在 active turn、runner、lease 或 attempt 时才 `204` 完成清理，否则 `202 session_revoking`，fence／取消尚未发送副作用的 runner，并在其 quiescent 及可能费用保守结算后清理；`POST /api/v1/assistant/questions` 接受有界问题、可选当前公开 path、必填 `Idempotency-Key` 和可选数字 `Last-Event-ID`，以 `text/event-stream` 只发送 `checking | retrieving | composing | validating` 阶段事件以及一个 `answer | refusal | error` 终态。应用拥有的 event journal 每 turn 最多保存 16 个带单调序号的事件；同 session、同 key、同 payload 的 `fetch` 重放只返回 cursor 之后的持久事件或已持久 terminal，且不产生第二次 provider 调用，同 key 不同 payload 或无效 cursor 返回 `409`；若原始 terminal 已按滚动／TTL 策略清除但无正文幂等 tombstone 仍在，则返回 `410 idempotency_result_expired`，绝不重调 provider。每 turn 同时只允许一个 live SSE subscriber、每 IP 最多三个，重连取得 slot 后可先重放 journal 再跟随 runner，超限返回带 `Retry-After` 的 `429 stream_connection_limited`。准入后 graph runner 与 HTTP transport 解耦，客户端断开不取消已开始的 provider attempt；进程重启时未开始副作用可恢复、已完成 attempt 可复用、`sending`／未知 attempt 只保守结算并写安全 error。SSE 不发送 token 或未经验证的答案片段；所有 event name/id 和 machine code 取固定枚举，`data` 用单行 JSON 序列化并转义 CR/LF，terminal payload 使用版本化 allowlist 字段 `event_id`、`turn_id`、`type`、`code`、`message` 以及仅 answer 终态可有的 `answer`／`citations`／`sources`。流开始前统一使用 `400 invalid_request`、`401 assistant_session_missing|assistant_session_expired`、`403 origin_rejected|csrf_failed`、`409 idempotency_conflict|event_cursor_invalid`、`410 idempotency_result_expired`、带 `Retry-After` 的 `429 rate_limited|concurrency_limited|budget_exhausted|stream_connection_limited` 或 `503 assistant_disabled|assistant_not_ready`；已接受问题的 `prompt_blocked|out_of_scope|insufficient_evidence|provider_result_unknown` 只作为 SSE refusal/error 终态。全部响应 `Cache-Control: no-store`。
- AC-5: session bootstrap 在任何付费调用前校验严格 payload、精确同源 `Origin`／Fetch Metadata 和独立创建速率，但因客户端尚无助手 CSRF 而不要求 double-submit；它只签发高熵新 cookie/CSRF 或幂等返回当前 session，所有 token／HMAC 校验使用恒定时间比较。其后的 questions 与 DELETE 在任何模型或 query-embedding 调用前执行 payload 字节／字符数、Unicode 规范化、控制与双向字符、精确同源 `Origin`、session-bound double-submit CSRF、session TTL、当前 path allowlist、速率、并发和费用准入；浏览器不得提交页面正文、任意 URL、system prompt、模型参数或检索 top-k。问题默认上限为 500 个 Unicode 字符，`Idempotency-Key` 只接受 16–128 个 base64url/UUID 安全字符并以 HMAC 连同规范 payload 摘要保存，所有上限均为有界显式配置；当前 path 只有在服务端解析为当前公开内容时才作为可移除的排序 boost，不能形成硬过滤或授权依据。转发客户端 IP 只在直连 peer 命中显式 trusted-proxy allowlist 时读取一个已配置 header，解析为合法 IP 链并从右向左剥离可信 hop 后取最右侧不可信地址；header 冲突、畸形链或无法唯一解析时拒绝，不信任客户端自报的左侧值，否则使用直连地址。缺失／伪造 origin 或 CSRF、过期会话、非法输入与非法 path 在付费调用前使用 AC-4 的稳定错误契约失败。
- AC-6: 不设置“每会话最多 N 问”，而以服务端持久、并发安全且分层的限额控制滥用：所有助手请求先受每规范 IP 30 次／分钟的廉价 envelope 限制，session 新建另限 5 次／10 分钟；通过 request shape、origin、CSRF 与 session 校验的每个新 idempotency key 都立即计为一个问题，即使随后被 scope／injection／无证据门拒绝，同 key 重放不重复计数；问题限额为 3 次／分钟且 10 次／10 分钟。通过确定性守卫后，第二个 runtime control 事务取得最多 1／session、2／IP、3／全局的带 fencing token／心跳／到期时间并发 lease，并把 Chat reservation 作为继续 turn 的硬前提；同一事务尝试 query-embedding reservation，余额不足时不拒绝 turn、不创建 Embedding attempt，而是持久标记 dense skipped 并走 FTS-only。竞争请求不能超卖 slot 或预算，所有付费节点发送前及 runner/event/checkpoint/terminal 写入前都重新校验 session tombstone、lease 和 fencing token，旧 owner 或已撤销 runner 不能发起／提交 provider 结果。IP 用 master secret + 北京日期派生每日短期 HMAC，但在跨零点后的最大 10 分钟窗口及全部旧 lease 存续期内，准入必须同时计算并合并今日／昨日 key 的 rate event 与 active lease，避免午夜重置绕过；它是伪名标识而非匿名化。`429 Retry-After` 按速率窗口最早释放、北京时间预算零点或并发 lease 最早到期保守计算为非负秒数，不承诺未知 provider 完成时间。session 采用 256 KiB 原始持久化上限和最多 100 个完成 turn 的滚动保留，且 transient query vector／parsed result／event payload 都计入上限；超过时先清除最旧原始历史／event journal、保留无正文幂等 tombstone 并按 AC-4 返回 `410`，不拒绝新问题，模型仍只看 AC-9 的更小上下文。失败、取消、超时和重启回收 lease，但不能把 `sending` attempt 当作从未调用。
- AC-7: 公开 Chat 新调用的北京时间自然日准入／预留硬上限为 2.00 元人民币，使用整数 micro-CNY 或等价 fixed-point，每次换算向上取整且不使用浮点累计；该上限不承诺异常后的结算值或供应商真实账单绝不超过 2 元。部署价格按所选模型的输入／输出每百万 token 人民币成本显式配置；每个 turn 在首次 Chat 调用前按“一次生成、一次校验失败后的重新生成”以及 system/schema/history/evidence 全部输入与输出硬上限预留最坏费用，reservation 永久绑定创建时的北京时间日期以及不可变 provider/model/version/价格快照，跨午夜完成仍结算回原日桶。余额不足时不调用 provider，并以 AC-4 的 `429 budget_exhausted` 拒绝。每次 provider 调用创建独立唯一 attempt 与上限，只有 `prepared` 可恢复；在任何网络字节发送前必须以短 runtime control 事务原子提交 `status= sending`、fencing token、request fingerprint 与费用上限，事务提交成功后当前 owner 最多发送一次。崩溃在该提交之前可安全恢复，提交之后即使尚未真正发出也一律按结果未知处理、不自动重发并按预留上限保守结算。允许的一次重新生成也必须消费单独 attempt 且已包含在预留中；已完成 attempt 复用持久化 allowlist parsed result，已知 usage 按价格快照结算并释放未使用 reservation。usage 缺失、不一致、包含未配置计费类别或超过预留上限时按可知较高值记账、允许该异常结算额超过 2 元并立即打开阻止后续调用的 billing circuit breaker，不得按零费用或截断到 2 元处理。query-embedding 与 index-embedding 使用 AC-3 两个独立的北京时间日预算池、价格快照和同样 write-ahead 的幂等 attempt 语义，但前者位于 `assistant_runtime` 且只由 API 使用，后者位于已备份的内容事实库且只由索引 Worker 使用；两进程不共享 runtime owner、连接或表。同 turn 重放不得重复 query embedding，query 池耗尽或结果不明时降级到 FTS。Worker 只有在内容库 index attempt 仍为 `prepared` 且 index 池不足时才可延后到下一个北京时间零点；一旦 `sending`／结果未知就不得自动重发，任务必须进入需运维处置且阻止 generation 激活的安全状态。显式 readiness 探针不进入公共 2 元桶或两个 Embedding 桶，但其预估费用必须在执行前展示并由部署运维预算承担。
