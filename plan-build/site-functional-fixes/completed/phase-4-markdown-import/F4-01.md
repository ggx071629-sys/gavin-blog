# F4-01 · 重建换行对照样本并确认解析修复边界

状态：完成。运行：`.run/site-functional-fixes/20260912-02/`。

## 事实

- 解析入口：`apps/api/app/routes/admin_content.py::parse_markdown`。
- 根因：用 `document.startswith("---\n")` 与 `split("\n---\n")` 判断 front matter；CRLF 文档首行为 `---\r\n`，被误判为缺少 front matter 并返回 422 `front matter is required`。正文中的 CRLF 也会原样进入存储。
- 既有契约：最多 50 个文件、单文件 2 MiB、批次 10 MiB、front matter 64 KiB、拒绝 anchor/alias、整批任一失败不写入、导入只创建草稿、重复 slug 409、ZIP 仅导出。

## 关键决定

- 只在解析前统一换行（含单独 CR），不放宽任何 front matter/YAML/编码校验。
- 正文与元数据采用同一归一化，保证 LF/CRLF 同内容得到一致结果。
