# 账号管理设计

## 账户边界

已确认：单管理员、服务器固定登录名；安全邮箱由服务器配置、页面脱敏、不在线换绑。个人名片公开邮箱与安全邮箱完全独立。不新增注册、多账户或日常登录验证码。沿用写作台 UI。

实施前代码事实：`AdminPassword` 在进程启动时从配置生成 Argon2 哈希；`AdminSession` 仅有创建和到期时间。阶段二已迁移为持久凭据、公开会话 ID 与最近活动时间；认证继续通过数据库会话 Cookie 与 CSRF。

## 凭据与恢复

已确认：已登录改密需要当前密码和邮箱验证码；忘记密码通过固定邮箱验证码重设。任何改密、重设、终端应急重置均撤销全部会话，包括当前会话。新密码持久化安全哈希，重启不得被配置覆盖。

设计决策：SQLite 单例凭据表（id=1）保存 Argon2id 哈希和递增版本。Alembic 建表；首次认证初始化仅在记录缺失时原子插入配置密码哈希，已有记录绝不覆盖。旧会话迁移时撤销，要求重新登录。密码核验与新会话创建必须在同一序列化事务中，防止旧密码并发登录绕过撤销。密码更新、验证码消费、凭据版本递增和删除全部会话在同一事务提交。

终端使用 getpass 双次输入，复用密码策略与事务服务；不接受命令行明文密码，不输出密码、哈希或验证码；必须明确目标数据库并停服备份后操作。邮件不可用时此路径仍可恢复。

## 邮件验证

实现默认值（A1-02 设计选择，非用户指定）：6 位均匀随机数字、10 分钟有效、同用途 60 秒重发间隔、每码最多 5 次错误尝试；账号跨用途每小时最多 10 次、每日最多 20 次发送预留。IP 每小时最多 20 次发送请求，键使用直接连接地址、不信任任意转发头。限额持久化，重启不清零；达到限额返回 429 与 Retry-After。匿名恢复会消耗固定邮箱配额，存在恶意耗尽导致暂时无法邮件恢复的风险；终端恢复独立可用。不锁日常登录。

新密码采用 15–128 Unicode 字符，不 trim、不强制字符类别；拒绝全空白、单一重复字符、与用户名相同及常见弱密码清单，不允许与当前密码相同。既有配置密码可迁移登录，首次改密/重设才应用新策略。参考 [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html) 的单因素长度建议，不宣称完整 NIST 合规。恢复码生命周期参考 [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

发送协议：短事务预留配额并创建 pending challenge（随机公开 ID、用途、凭据版本、到期、尝试数），在事务外以 TLS SMTP 有界超时发信，然后短事务将同一 challenge 激活。邮件失败/结果未知均不能使用该码，也不退还预留配额；不自动重发。只有成功激活的新码替代旧码；较早发送回调不能覆盖较新记录。每个用途最多一个可用码；凭据变更使所有用途码失效，包括在途发送。

码只存带服务端独立秘密的 HMAC 摘要，输入绑定 challenge ID、用途、凭据版本和配置邮箱；不能对 6 位码只做裸 SHA256。秘密未配置时邮件功能失败关闭、普通登录与终端恢复仍可用。配置邮箱或秘密改变使旧码无效。SMTP 授权码及 HMAC 秘密不进入 OpenAPI 示例或日志。

提交时在数据库串行写事务内复检会话、当前密码（改密）、用途、版本、状态、到期与尝试次数；错误次数必须提交后再返回错误。验证码错误/过期/已使用统一返回 400 invalid_code，避免泄漏状态；当前密码错误返回 400 invalid_current_password，并应用账号/IP 持久限流。正确码最多一次提交成功，其余并发请求拒绝。策略不符 422，未认证 401，CSRF 错误 403，SMTP 配置/发送失败 503 mail_unavailable。认证状态异常时不得继续提交。

仅发送到配置邮箱。改密和恢复验证码用途隔离；不得把验证码、授权码或完整邮箱返回浏览器、写日志或归档。开发测试用注入式邮件替身，真实验收必须分开记录 SMTP 接受与收件箱收到。

## 会话

已确认：展示登录时间、最近活动时间、当前会话标记；可退出单个会话或其他会话。服务端返回独立公开随机会话 ID，不能返回会话 Cookie 或 token_hash。只列未过期会话；最近活动以认证请求观察时间更新，UTC API 时间由浏览器本地化。

删除当前会话跳回登录；删除其他会话保留当前会话。会话撤销后下次认证请求必须 401，已进入执行的请求不回滚已提交的业务。安全写操作在写事务内重新验证会话有效性，避免依赖注入后的撤销竞态。

### 跨端契约（API 前缀 /api/v1）

全部账号响应 no-store；会话 Cookie 继续 HttpOnly、SameSite=Lax、生产 Secure。认证写请求用会话 CSRF；匿名恢复写请求用现有 `/auth/csrf` 双提交校验。错误 detail 使用稳定码，前端映射中文，不回显 SMTP 异常。

| 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- |
| GET /auth/account | 已认证 | username, email_masked（未配置为 null）, mail_available |
| POST /auth/account/code | current_password；会话 CSRF | 202 challenge_id, expires_in=600, retry_after=60 |
| POST /auth/account/password | current_password, new_password, challenge_id, code；会话 CSRF | 204，删除 Cookie 并清全部会话 |
| POST /auth/recovery/code | 匿名 CSRF，无邮箱/用户名输入 | 202 challenge_id, expires_in, retry_after；不返回邮箱 |
| POST /auth/recovery/password | new_password, challenge_id, code；匿名 CSRF | 204，删除 Cookie 并清全部会话 |
| GET /auth/sessions | 已认证 | items[{id, created_at, last_seen_at, is_current}] |
| DELETE /auth/sessions/others | 会话 CSRF | 204，仅保留当前会话 |
| DELETE /auth/sessions/{id} | 会话 CSRF | 204（不存在也幂等）；当前会话删除 Cookie |

code 输入严格 6 位 ASCII 数字，challenge_id 与 session id 为不可预测随机值；所有字符串有长度上限，禁止额外字段。会话公开 ID 与 token_hash 独立。静态 `/others` 路由优先于参数路径。日期 ISO 8601 UTC；会话列表按创建时间与 ID 倒序，最多 100 个活跃会话，登录事务清理过期并裁剪最旧会话。

### 迁移与邮件配置

新增 Alembic revision，建立单例凭据、挑战、发送/核验配额表，添加公开会话 ID 与 last_seen_at；升级清旧会话，保留业务表。迁移不读取 .env、不向数据库写明文密码。初始化依赖已迁移表，缺迁移清晰失败，不用 create_all 绕开迁移。SQLite BEGIN IMMEDIATE 负责跨进程串行认证写入；SMTP 在锁外执行，失败不能长期占有写锁。

配置使用现有 GAVIN_ 前缀：admin_email、smtp_host、smtp_port、smtp_username、smtp_password（邮箱授权码）、account_code_secret（独立随机秘密）。SMTP 仅 SSL/TLS 加证书验证，不提供明文降级；10 秒网络超时；固定配置发件人和收件人允许同址。缺少任一必要项表示 mail_available=false；不妨碍登录与应急恢复。SMTP accepted 只能表示服务器接受，前端文案为“已提交发送，请检查邮箱”，不声称收到。

真实 163 host/port 与授权码开通操作在实投前按官方资料复核；配置只进被忽略本机文件。测试通过注入 sender 捕获邮件，不新增返回验证码的调试 HTTP 接口。OpenAPI JSON 与 api-types.d.ts 由现有 contracts 命令生成；Web 消费模型显式同步。

## 页面与状态

`/admin/account` 属于运营导航，使用 admin-core 布局和现有表单/按钮/弹窗；三块开放设置分区：只读账号信息、修改密码、登录会话。设置说明与内容桌面并列、手机纵向；继承 studio 双主题变量、本地字体、44px 触控目标与分隔线。沿用 `profile.vue` 的表单层级，不复制原型的账户专属视觉证据。

改密表单：当前密码、新密码、确认密码、验证码；发送按钮独立于提交，倒计时只辅助服务端限流。提交前说明将退出所有设备并单独确认。密码/验证码不持久化浏览器存储。失败保留可纠正状态，成功清空敏感输入并跳登录提示重新登录。

登录页提供“忘记密码”至 `/admin/recover`，账户页也提供恢复入口。恢复页采用现有居中登录外壳和主题切换，固定邮箱说明、验证码、新密码及确认；没有邮箱输入、账号枚举或注册。提供返回登录。

读取、发送、提交、撤销分别有忙碌/失败/重试反馈；同动作禁止重复提交。401 清除敏感表单并回登录，403 提示刷新验证，429 显示服务端等待时间，邮件失败不显示成功。会话时间有语义标签，空态与读取失败分开，错误 role=alert，成功 aria-live，控件有 label，键盘可用。
