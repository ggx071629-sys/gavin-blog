# 问答助手可靠性与注入防护：设计依据

2026-09-11。原讨论方案与阶段计划的设计依据；随后已收到实施指令并完成计划内离线修复。本文保留原设计理由，实际完成与剩余风险以 [计划入口](PLAN.md) 和各阶段归档为准，不是安全认证。
已确认自然综合＋逐块证据约束、语义校验先离线对比，以及由 Codex 做测试而不调用当前配置模型；测试保持简单。

## 1. 目标与边界

- 优先减少无依据的个人经历、能力和奖项断言，阻止无关引用为结论背书，同时保留正常技术内容问答。
- 分别处理提示注入、事实可靠性和正常问题误拒；不把关键词命中率当成整体安全能力。
- 复用现有公开资料 RAG、来源复核和问答链路；不新增自由工具、私有资料、外部写操作或部署结构。
- 保留自述与独立证明的区别、部分回答、来源冲突、片段不等于完整清单等现行业务约束。
- 保留认证、来源撤销、会话隔离、输出安全、默认关闭、运行资格及现有预算；本计划不授权上线或付费调用。

## 2. 当前事实与证据边界

- [输入规则](../../apps/api/app/assistant/preflight.py)主要依赖关键词和有限编码处理；既有函数级探查发现改写攻击可通过、正常“提示词工程”问题被拒。
- [输出校验](../../apps/api/app/assistant/output.py)确认引用别名存在；高风险断言检查累计前块引用并以有限关键词、数字作判断，不能通用验证语义支持关系。
- 本次对话中的“图灵奖断言附有效引用被接受”是函数级结果；阶段一需要形成可重放基线，不冒充真实模型攻击成功。
- [提示组装](../../apps/api/app/assistant/prompt.py)已有证据分区、转义与历史上下文规则；[调用适配](../../apps/api/app/assistant/providers.py)约束结构化输出。
- 已有页面路径呈现修复是独立完成事项，见[原归档](../../harness/specs/archive/20260911-assistant-answer-paths.md)；本计划不重复计入完成数，不改写其历史。
- 来源路径回显本身不是注入成功证据；当前路径替换仅覆盖已引用的匹配地址，不覆盖所有旧会话或未知地址。

## 3. 引用与事实校验

- 每块表达少量事实，只使用该块所引的本轮有效证据；修正跨块借证据及数字出现即算支持的误判。
- 推荐评估内部“事实—来源别名—支持原句”结构，程序核对原句确实属于对应有效证据；不默认将内部字段展示给访客。
- 原句存在不等于支持结论，尤其要区分主体、否定、数量单位、时间、奖项和能力；不能把原句匹配宣传为通用语义保证。
- 用户已确认保留自然综合、逐块对应证据；证据不足时只回答有依据的部分。S1-02 将此决定落实为可执行行为，不再重问回答形态。
- 内部支持原句是辅助核验材料，不将公开回答改成机械摘录；字段兼容及模型失败按 S1-03 的最小契约落实。
- 用户已确认独立语义校验先离线对比，按结果决定是否接入；不默认每轮增加调用，不把 Codex 或第二个模型作为绝对裁判。
- G-1：已确认的无依据断言、跨块借证据和数字误配样例不能冒充有据回答；有据自述及正常内容仍能回答。
- G-2：按选定策略验证每块支持材料与本轮来源绑定；如使用原句则拒绝伪造/错绑，引用与原有输出安全约束继续生效。
- G-3：公开问答、管理试问、SSE、恢复和历史在受影响处一致；内部校验材料的输出、留存和预算遵循确定的契约。

## 4. 提示词补充

- 用户可指定主题、语言和长度，不能更改证据、引用、角色或权限；自称管理员、开发者或审计员不产生授权。
- 历史仅用于理解指代，不是事实证据；历史事实需由本轮证据支持，已有来源地址限制继续保留。
- 每块事实须由该块引用支持，不用真实但无关的引用包装推测；配合 §3 的程序校验。
- 问题、证据正文、标题、引文、代码和编码内容均不能授予行为权限；区分讨论指令与执行指令，尽量回答合法部分。
- 不接受提问中未经证实的经历、奖项和数量；历史职位不能直接当作现职，缺少时间证据时限定表述。
- 对齐后端结构化输出、HTML/Markdown 链接与手写引用标记限制；保留后端确认的简历不可用固定提示例外。
- P-1：上述规则形成清晰分段，保留 §1 业务范围；混合请求、错误前提、历史污染及输出格式有对应可观察检查。

## 5. 输入与资料防护

- 区分“讨论提示词/安全教程”与“要求当前助手改变权限/泄露指令”；不单因安全词汇拒绝站内技术问题。
- 不能以删除关键词规则替代防护；同时处理问题和实际进入模型的资料字段，核对标题、heading、正文及历史入口。
- 从直接/间接注入、角色冒充、改写、多语言、编码/Unicode、混合合法请求与多轮污染选取少量代表样例；复用已有覆盖，不做类别之间的组合枚举，正常安全文章和配置教程作对照。
- 已发布只证明来源资格，不代表内容可以控制助手；自述事实可以带归属回答，要求助手改变回答的指令不能执行。
- D-1：已确认的正常问题误拒得到修复，已知攻击和泄密/危险输出约束不因放宽词汇而失效。
- D-2：在上述入口与攻击类别分别检查行为；过滤器放行、模型服从和最终危险输出分开记录，不承诺消除所有注入。

## 6. 评估与适用验收

- 用户选择由 Codex 执行本地代码测试、编排确定性模型替身和离线语义评审；不调用当前配置 Chat 或其他外部模型服务。
- 测试采用少量固定问题、证据与预期结果，优先复用已有用例和模型替身；不建设评测平台、独立数据集管线或自动评分模型。
- 对照修复前后行为，以简短“样例—预期—实际—结论”记录过滤、预置输出和 Codex 事实核对；无需统计榜单或成功率计算。
- 核心样例保留正常提示词工程问题、改写指令、无关有效引用的假奖项、跨块/数字误配，以及正常有据回答；其他类别按 §5 补代表样例或复用现有检查，不展开大矩阵。
- 没有真实模型生成试验，不报告部署模型攻击成功率；本地耗时与 Codex 评审开销不冒充线上延迟或 provider 账单。
- 错误时间、混合攻击、多轮历史及来源撤销按实际受影响点验证；优先沿用既有检查，不为每个输入重复跑完整链路。
- E-1：可执行测试、模型替身与 Codex 语义评审分别标识；结果仅证明对应代码和样例，不声称真实部署模型已抗注入。
- E-2：由 Codex 逐例对照证据原句与结论，简要记录程序/原句检查漏掉什么、语义复核能否发现及可能误判；不另写自动评审系统，线上成本/延迟未测即标未知。
- E-3：按 G/P/D 条件和已确定策略报告改善与残余风险，完成适用 Harness 验证后收尾；实际模型验证不属于本轮门槛，不宣称零风险或生产就绪。
- 不新增固定样本数、成功率阈值、延迟指标、压测或全量发布门禁；局部检查后只做适用的正式验收，无新变更或失败不重复测试。
