## 设计与现有能力的差异

- 搜索 API 没有类型筛选参数，本阶段将类型改为明确的范围说明，不制作无行为的筛选按钮。
- API 没有项目结构节点、技术栈或节点解释字段。结构图使用作者已有 Markdown 的图片/Mermaid；不把原型中的本站架构样例或推断拓扑写入真实项目。没有图也有完整的标题、元信息、正文和关联区。
- 真实项目和读书可以为空；审查中的书籍、文章、项目和封面均由隔离测试接口生成，不改开发数据库。封面接口要求绝对 URL，沿用原合同。
- 独立公开样式表在现有全站样式之后加载，选择器限定公开页面与阅读容器。主题 token、字体、后台外壳、首页和助手准入不变。

## 验证与证据

实施检查使用真实隔离 API 发布，并实际走列表、搜索、目录、脚注和关联链接。项目与书摘发布后再修改工作副本，公开页与搜索继续显示旧发布内容；canonical 和对应 JSON-LD 同时核对。

新增矩阵覆盖全部十类公开页面/状态、浅深主题、320/390/639/640/768/1024/1100/1101/1280/1440px、480px 短视口、长连续标题、单行/多行代码、宽表格、真实/缺少封面、无结构图。截图和 axe 分别记录；生产构建还复用完整公开页面矩阵与 Lighthouse 四项 90 分门槛。

执行入口：根目录的 `npm run test:web`，Web workspace 的 `typecheck`、`lint` 与选定 Playwright 场景；最终在 `harness/` 执行 `python -m tools.harness verify 20260906-public-reading --close`，按影响计划精确执行阅读、项目/书籍、栏目/归档/关于、搜索、SEO、Mermaid、生产视觉与失败态检查。正式通过状态、AC 覆盖、测试计数、日志来源及隔离清理由 [机器证据](../../../harness/verification/evidence/20260906-public-reading.json)判定，不用静态截图代替业务验收。

实施中发现并修复：CSS 加载顺序导致旧 720px/首段/代码样式覆盖；移动单列网格需同步覆盖行定位；深底代码行号对比度不足。另修正测试封面 URL 和 Windows 剪贴板换行断言，未改变产品接口或降低门槛。

两次正式 E2E 启动超时已保留失败证据。诊断 HTTP 500 的 Vite 详情发现独立 `.nuxt/e2e` 首次启动时，项目 tsconfig 引用的默认 `.nuxt/tsconfig.json` 尚未生成。最终顺序先运行包含中文标题锚点单元检查与生产构建的 Web 质量门禁，再运行 E2E，使既有 Nuxt prepare 前置产物就绪；不修改 Harness、不提高超时或降低门槛。中文目录 href 额外进行 URL 片段编码，保留原有百分号编码的标题 ID，避免路由解码后找不到标题。

开发版 404 的 Nuxt 调试浮层本身包含嵌套控件；E2E 的 404 axe 范围限定为实际 `.public-error`，正式生产矩阵仍扫描完整页面且已通过，不忽略任何产品控件。

多栏目筛选条保留内部横向滚动，避免栏目增长不断抬高正文；边界宽度检查等待 resize 后的绘制帧，并在同一次 DOM 读取中比较姓名与简介的位置，避免将断点两侧的测量混成一次布局断言。

既有关于/文章索引回归仍断言第二阶段已移除的 `.home-profile` 和首页旧 `article-card`；更新为当前 `ProfileCard` 与重点文章组件，并核对实际城市、技能和发布标题。产品首页不因此改动。

正式精确引用 runner 的多组 E2E 共用同一次任务的隔离数据库；空归档用例改为先发布一个准备样例，再清理该隔离库的文章并检查 HTTP 200 与空态，消除“必须先执行”的隐藏前提。该操作只通过测试 API 执行。
