## 核心路径与共同样式

| 路径 | 验证依据与边界 |
| --- | --- |
| 登录 → 新建/自动保存 → 预览 → 发布 → 公开阅读/搜索/SEO | 隔离真实 API 和临时数据库；三类内容均验证发布快照，工作副本不提前公开；错误注入明确标识 |
| 栏目/名片 → 公开首页与列表 | 实际维护接口及公开读取，不用原型计数或假资料替代 |
| 媒体 → 编辑器 → 发布；导入 → 草稿编辑；回收站 → 恢复 | 隔离上传及导入资源；复制/重试/冲突/批量失败分别可见；导出不等同全站备份 |
| 问答 → 本轮引用 → 原文 → 焦点交接 | 本地离线回答器与真实隔离服务；检验交互与引用合同，不推导云端回答质量或生产资格 |
| 全站双主题与样式隔离 | 首页/文章列表相互不污染，公开与后台代码块均有主题断言；各阶段布局矩阵重跑，包含长文本、无封面、空数据、表格局部滚动 |
| 故障与无障碍 | 独立失败上游验证 SSR 状态、空数据、404/500、session/login/logout；生产和 E2E axe、键盘与焦点断言保留原门槛 |

## 本轮验证

初轮在固定 HEAD 的 detached 检出 `.run/p7/` 执行 `npm run quality:release`；正式门禁由 Harness 创建并清理独立临时检出。依赖通过本仓库现有目录链接，未安装或升级。主工作区的 `.env`、内容数据库及媒体不复制到候选中。完整入口顺序包含 API lint/typecheck/tests、Harness tests、OpenAPI/派生类型一致性、Web 类型/Lint/单元/生产构建/质量/失败态、完整核心与助手 E2E、Harness 完整性。

首次候选失败：生产矩阵捕获文章新建页 critical `aria-valid-attr-value`。`WritingWorkspace` 的预览按钮指向尚未挂载的 v-if 区域；现保持带 ID 的空容器存在且隐藏，内部预览说明和 slot 仍仅在预览模式挂载。三类新建/编辑的初始 axe、唯一目标、按需渲染和返回 Markdown 检查加入原有 `desk layout`，没有豁免规则。原始失败日志仅本地 `.run/p7-review/release.log`；该轮生产质量 9 项通过、1 项失败，后续失败态与 E2E 未执行。修复后正式执行 `python -m tools.harness verify 20260906-ui-delivery --close`，release profile 运行完整发布门禁。未设置 `HARNESS_BASE_REF` 的 release 明确为 local-only 候选门禁，不作为远端变更覆盖或上线证明。

## 集成测试与当前设计的差异

完整核心 E2E 发现旧首页/关于文案与 `article-card` 定位未随阶段 2/3 更新；改为当前文案、真实 profile、重点条目及连续列表，种子文章仍逐一核对公开路径。恢复项目后原断言错误地要求整库回收站为空；归档测试在同一隔离库留下其他回收条目，现核对目标已离开回收站且公开接口重新返回原项目。代码块的两种主题均使用深色容器和同一语法色，旧测试要求关键字变色且把透明背景/color(srgb) 当黑色；现使用真实容器背景和浏览器颜色转换，保留正文 4.5:1 门槛，增加全部语法 token 的同门槛检查及容器随主题改变断言。以上修正不改变产品配色或放宽阈值。双主题几何测试同样迁移旧 `.home-article-grid` 等定位，验证介绍/栏目双列、名片合组及下方条目。首轮正式执行核心 65 项通过、6 项旧断言失败、1 项原有可选截图跳过；助手组因核心失败未启动。

完整 release 在未运行助手组时已接近 900 秒：API 269 项约 113 秒、Harness 245 项约 73 秒、Web quality 约 309 秒、核心 E2E 约 360 秒，另有启动/类型/契约开销。将 `release.timeout_seconds` 从 900 提高到 1200 秒，保留终止机制、所有 leaf 命令及 90/4.5:1 阈值。该变化仅增加整组执行预算。

恢复执行的 `84f863c` 完整门禁中，API 269、Harness 245、Web 单元 153、生产质量 10、故障态 8、核心 E2E 71 项通过（另 1 项原有可选截图跳过），Lighthouse 为 96/100/100/100；助手组 4 通过、1 失败。失败停在后台旧标题“准入轨道”的可见性断言，阶段 5 已将实际标题改成“开关与准入”；更新精确标题定位；定向复核继续暴露不可用正则同时匹配标题和说明，现分别精确检查并增加输入禁用断言。另一条未读滚动用例在 smooth 滚动发生前立即取值，现条件轮询等待位置实际变化，仍检查原位置不被新回复抢走及最新回复进入视口。保留真实 PATCH、停用状态、无障碍、不同宽度和禁止后续提问请求检查。另一次验证因会话中断停在 API 测试，保留为中断，不计通过。失败证据和日志保留于本地 `.run/p7-review/`。
