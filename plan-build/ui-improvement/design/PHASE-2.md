# 第二阶段：首页与主要图形

任务 `20260906-home-atlas`；基线 `975cb297e3a41d069aec3a9126f3974d878d638e`；规格首次提交 `584a112`。设计依据为本地 `plan-build/ui-improvement/design/PROPOSAL.md` 的第二阶段及内容增长规则。

## 实施范围

- `/`：真实作者简介、头像与联系入口合组；取消首页的在线暗示与孤立侧栏；保留主题、字体和 SEO。
- `HomeAtlas`：按栏目 id 选取最多三个，每栏一篇最新文章；文字、数量、栏目筛选和阅读链接来自现有 API。点击、触摸、Enter/Space 保持选择；悬停和焦点临时突出直接分支；重置清除。说明与链接始终可读。
- 最近内容：一篇重点文章及最多三条紧凑条目；缺摘要不留空卡。不从文章标题推断技术结构，不使用写死的 SSL 配图。
- 手机改为每条分支内栏目在上、文章在下，保留自然文字尺寸和左侧关联线；点阵只位于图形范围。减少动态效果时直接切换。
- `ProfileCard` 增加首页 `intro` 变体；后台默认预览及既有编辑、可见性和邮箱复制行为继续复用。阶段三至七不在本次迁移范围。

## 数据和失败边界

一次首页加载最多六个 API 请求：共享 Profile 一次、taxonomy 一次、最近四篇一次、最多三个栏目单篇请求。无现存栏目复用最近文章，不增加回退请求；无轮询或自动重试。每栏最新按现有接口的 `published_at DESC, id DESC`，不是编辑时间。总数直接读取 taxonomy，包含未分类和已删除栏目的公开快照；不添加没有接口依据的筛选。

客户端导航有显式加载状态；空站正常显示 200 空态；有文章无栏目显示最新文章入口。taxonomy 失败不显示假零篇；单栏目失败与分次读取期间的空结果分别说明并保留栏目链接，手动重试重新读取。主要文章或 Profile 读取失败沿用现有错误页面和 HTTP 分类。SSR 请求通过 Nuxt 上下文执行，水合不重复取数。

首页序列化投影只保留 id、标题、摘要、发布时间和 public_path，不重复把全文放进 HTML；**现有上游接口仍传全文**，不能把页面投影当成后端流量优化。

## 验证与测量

实施期间 Web 单元 153 项通过；新增四个浏览器场景已验证真实隔离发布、草稿不外泄、稳定栏目选择、加载/空态/局部失败/重试与双主题长内容。生产构建通过。生产首页的真实 API 样例与双主题 axe 检查通过；最终验收以 [机器证据](../../../harness/verification/evidence/20260906-home-atlas.json)的状态、AC 和隔离清理结果为准。

结果支持本阶段继续使用现有 API；正文增长仍会放大上游流量，当前未新增轻量聚合接口。Lighthouse 90 分门槛继续保留。一次正式尝试首次性能 81、自动重试 97，其余三项 100；该尝试按失败保留，没有用重试成功冒充认证通过。后续诊断报告及最终分数见本机执行日志，最终成功与否由上方机器证据判定。

Windows 隔离环境须使用与依赖同盘的短临时路径（本次最终验证采用 `D:/t`），避免 C/D 跨盘 Nuxt 类型路径和长路径诊断导出失败；没有修改验证器或降低检查范围。

实际截图与原始日志只保存在本机测试产物中，不提交 Git。测试使用隔离数据库，不改开发内容库。
