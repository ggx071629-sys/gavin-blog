## I004 · 客户端进入列表失败时地址与内容不一致、无恢复入口（高）

- P5-02/P6-03：从首页点击文章，将目标 articles 列表请求受控返回 503；地址变为 `/articles`，H1 仍是首页“开发笔记、项目记录，还有读书心得”，没有错误或重试入口。
- 独立访客再次复现：从关于页点击读书，books 请求 503 后 URL `/books`，仍显示“你好，我是 审查用户。”，重试按钮数量 0。
- 解除注入并刷新可恢复；搜索的后续请求 503 则正确显示错误页并保留关键词重试，两者不能混为全部错误态通过。
- 证据：issue-004-stale-home.png、issue-004-stale-about.png、issue-004-public-console.txt；控制台 H3Error 来自 useApiFailure 初次 setup 抛错。
- 影响：用户看到错误页面内容且缺少操作内恢复方式。其他首次 setup 消费者可能同受影响，但尚不能仅凭共享源码认定全部复现。
- 建议优先修复客户端初次加载错误的页面级处理，再覆盖不同列表/详情路由回归；本轮未修复。

## I003 · 关于页自动保存清空尚未提交的标签输入（中）

- P4-01/P6-03：修改网站说明触发 PATCH，暂缓该真实请求；在第一项“新增领域标签”输入“尚未提交的新标签”；放行真实请求。
- 预期：无关字段的保存不删除正在输入的标签；实际保存成功后该输入由上述文字变成空字符串。
- 浏览器已用受控延迟独立复现，未模拟成功响应；放行后撤销拦截。证据 issue-003-tag-draft.png 与执行记录的前后值。
- 影响：用户输入静默丢失；建议仅清理已提交的临时输入，不在每次自动保存重建全部草稿状态。

## I001 · 读书媒体库封面选择导致保存失败（中）

- 用例：P3-03；页面 `/admin/books/24/edit`。
- 复现：书籍封面 → 选择已有媒体 → 来源上传图片 → 应用筛选 → 使用 URL。
- 预期：选择本站媒体后可保存封面；实际填入 `/api/v1/media/14/webp`，出现“请填写以 http:// 或 https:// 开头的有效封面 URL”，自动保存失败且阻止发布。
- 浏览器证据：`.run/site-functional-audit/20260912-0035/issue-001-book-cover.png`。
- 源码支持：BookNoteEditor 的 selectCover 直接写入相对路径，输入 type=url/pattern 及 WritingWorkspace 校验拒绝该值。
- 影响：媒体库选封面正常路径不可完成。手填完整本地 URL 后保存发布可恢复；该替代操作不抵消原流程失败。
- 建议：统一内部媒体地址与输入校验合同，优先修复；本轮未修改产品。

## I002 · Markdown 导入不接受 CRLF 换行（中）

- 用例 P4-05，回收站与迁移 → 选择 Markdown 文件。
- 从真实导出构造 UTF-8 Markdown，同一内容的 CRLF 文件返回 422 `front matter is required`；LF 文件成功创建草稿。
- 影响：Windows 常见换行文件被错误拒绝，页面只给 front matter/编码/slug 的笼统提示。
- 证据：same-crlf.md、same-lf.md、issue-002-crlf.png；仅存在本轮 `.run` 目录。
- 源码支持：admin_content.py 的 parse_markdown 直接检查 `---\n`，没有规范化 CRLF。
- 建议：解析前统一文本换行，并保留逐文件错误原因；本轮不修复。
