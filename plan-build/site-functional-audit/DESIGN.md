# 全站功能审查设计基线

依据：2026-09-12 用户与 Agent 已确认的审查共识；本文件固定范围和方法，不扩展产品规格。
本次交付仅为执行计划，不启动服务、浏览器审查、数据操作、产品实施或缺陷修复。

<a id="scope"></a>
## 1. 目标与范围

目标：由 Agent 实际操作浏览器，确认全站现有功能的用户操作与业务结果，先完成审查再汇总问题。
全站功能须从路由、组件与浏览器动态入口共同盘点，不能把下列模块摘要当作完整元素清单。
已安装的自动化测试可作参考或补充证据；通过测试不能替代本轮实际操作。
代码只证明入口或预期存在，未实际执行的功能不得记为通过。

- 覆盖公开页面、后台页面、跨页面功能，以及空状态、错误态、条件性入口。
- 元素包括按钮、链接、表单、菜单、弹窗、上传下载、分页及可操作的阅读组件。
- 共享组件验证通用行为，各页面仍检查对应业务结果。
- 排除邮件验证码的发送、收取、校验，以及依赖验证码的改密、找回密码闭环。
- 邮件排除说明为“用户已自行实测，本轮未复验”，不继承为本轮通过证据。
- 排除公开 AI 问答、后台试问及运营维护、AI 简历摄入/同步/引用质量；用户后续单独审计。
- 简历地址保存、可见性与普通附件访问仍属于资料功能，不因 AI 排除而跳过。
- 本轮不修复缺陷；输出问题、影响与建议修复顺序，不产生上线资格结论。

<a id="environment"></a>
## 2. 环境与数据

使用本地真实前后端、独立数据库、媒体目录、测试账号；不写入日常或正式数据。
记录代码版本、启动配置、实际浏览器、访问地址、运行标识及数据/证据路径；不得记录秘密。
复用现有隔离运行能力前先确认配置、目录和端口；不默认复用已运行的服务。
输入定位：[API 隔离启动器](../../apps/api/scripts/run_e2e.py)、[Web 隔离配置](../../apps/web/playwright.config.ts)。
这些文件提供启动参考，不直接启动全套 E2E，也不把配置存在视为环境已经可用。
测试数据涵盖文章、读书、项目、关于页、资料、栏目标签、媒体与 Markdown ZIP 样本。
按现有能力准备草稿、已发布、未发布修改、空状态、多页及阅读增强样本。
破坏性用例使用专属测试数据；保留其他审查依赖的样本，记录结束后的残留及处理情况。
正常业务使用真实接口，不用模拟成功响应代替保存或发布；异常注入只用于明确的失败态用例。
AI 功能保持不执行；资料操作若会触发 AI 后台任务，应使用隔离配置避免外部调用并记录边界。

<a id="account-resources"></a>
## 3. 账号与资源适用条件

登录与错误登录、后台访问、退出、账号信息、当前/其他/单个会话撤销均须按实际入口检查。
成功提示须与刷新或再次访问后的会话状态一致；失败不能假称成功，验证码相关闭环按 §1 排除。
栏目、标签须覆盖页面实际提供的全部增删改查、选择及校验行为。
媒体须覆盖上传、选择、展示、加载更多、去重、删除、恢复和实际存在的 Alt 等校验。
参考：[账号说明](../../apps/web/ACCOUNT-MANAGEMENT.md)、[资源页面](../../apps/web/pages/admin/media.vue)、[分类页面](../../apps/web/pages/admin/taxonomy.vue)。

<a id="content"></a>
## 4. 内容管理与发布适用条件

文章、读书、项目分别检查管理列表、新建、编辑、自动保存、实际支持的预览与发布。
列表包括搜索、状态筛选、计数、分页、条件清除、空状态、失败反馈与更多菜单。
编辑包括实际提供的内容/元数据字段、媒体引用、校验、保存状态、离页及重进结果。
保存后刷新或重新进入仍能读取正确内容；发布后访客列表与详情读取正确公开版本。
修改已发布内容但尚未再次发布时，公开结果保持发布快照；再次发布后核对更新。
独立预览、历史版本和回滚只验实际支持的能力，不强制文章、读书、项目功能对称。
参考：[Web 内容边界](../../apps/web/README.md)、[共用写作台](../../apps/web/components/WritingWorkspace.vue)。

<a id="profile-lifecycle"></a>
## 5. 资料与内容生命周期适用条件

关于页涵盖编辑、保存、预览、发布与公开展示；资料涵盖头像、身份、技能、渠道、可见性及附件。
公开模板未直接显示的字段须结合现有边界判断，不能仅凭编辑字段存在认定前台显示缺陷。
文章与关于页检查已有的版本列表、差异、回滚确认及结果；项目和读书不要求独立版本页。
内容回收站检查各支持类型的进入、恢复、永久删除、确认/取消及公开结果。
Markdown ZIP 导入检查实际支持的输入校验、结果反馈及草稿创建；导出核对下载文件内容。
参考：[Web 资料边界](../../apps/web/README.md)、[内容工具](../../apps/web/pages/admin/content.vue)。

<a id="public"></a>
## 6. 公开浏览与内容发现适用条件

涵盖首页与图谱、文章/读书/项目列表及详情、归档、搜索、关于页、导航和页脚。
检查列表筛选、分页、搜索关键词保留、空结果、正确 404 与上游错误的实际行为。
阅读覆盖实际支持的 Markdown、目录锚点、代码复制、公式、图表、引用与反链及局部滚动。
公开资料、联系方式、附件、外链与内容卡片应到达正确目标。
RSS、站点地图等输出检查能否访问及其公开内容范围，不另设性能或 SEO 评分门槛。
外部目标记录本站链接及可观察访问结果，外部服务故障不能未经分析归为本站缺陷。
参考：[公开路由](../../apps/web/pages/)、[阅读组件](../../apps/web/components/ReadingLayout.vue)、[服务端出口](../../apps/web/server/)。

<a id="method"></a>
## 7. 操作与核对方法

每条用例检查适用的交互反馈、持久化结果和业务结果；不要求无写入链接执行数据核对。
按钮有反应或接口返回成功不足以证明业务完成；保存、发布等需刷新/重进与访客端核对。
关键写入流程覆盖必填缺失、连续点击、保存中离页、请求失败与会话失效等相关状态。
失败态采用可控方式，记录触发和恢复方式；无法触发或观察时如实记录原因。
检查主题、菜单、弹窗确认/取消、键盘与焦点操作，以及页面实际存在的重试入口。
桌面端完整执行范围内用例；移动端检查每页入口及关键登录、编辑发布、搜索阅读等流程。
记录实际浏览器与视口；视口模拟不代表真机测试，不新增浏览器矩阵、性能或无障碍评分门槛。
遇到失败记录直接问题与依赖阻塞，继续其他可执行任务；不通过修改产品来绕过失败。
已有有效证据可关联复用，涉及不同内容类型、权限或页面业务结果时仍须独立核对。

<a id="reporting"></a>
## 8. 结果与交付

审查启动后在本目录建立以下工作记录，本次不生成空报告或预填通过结果：
- `COVERAGE.md`：页面、元素、功能/流程、用例编号、所属阶段、状态和关联记录。
- `EXECUTION.md`：环境与运行标识、前置数据、操作步骤、预期/实际结果、证据位置。
- `ISSUES.md`：缺陷编号、复现步骤、影响程度、受影响用例、依赖阻塞和建议修复顺序。
按功能或用例定位记录，不要求每轮全量加载报告；这些是交付记录，不拆分阶段当前任务。
原始截图、请求错误和日志留在仓库 `.run/site-functional-audit/<run-id>/`，不提交到 Git。
执行中功能结果区分通过、失败、阻塞、未验证；排除项单列理由。
审查结束时范围内每项须有通过、失败或明确阻塞；未验证不能静默算通过或无理由改成阻塞。
报告分别统计功能结果、排除项和任务进度，区分浏览器确认事实、源码推测及主观建议。
审查完成可以仍有产品缺陷；任务完成不等于产品全部通过，更不等于获得发布资格。

<a id="maintenance"></a>
## 9. 任务状态与归档

主计划状态使用未开始、进行中、阻塞、未验证、完成；已排除功能不列为待执行任务。
未开始：未执行；进行中：正在执行；阻塞：具体障碍导致不能继续；未验证：已有操作但缺证据或结论。
完成：该任务的审查、结果记录与交接已完成；已发现缺陷不妨碍审查任务本身完成。
等待前置的未开始任务保持未开始；已尝试且无法继续时登记具体阻塞及恢复条件。
整体报告可以交付已尽力查明的阻塞，但未执行或未验证的任务不能提前计完成、归档。
当前任务原地更新，主计划保留仍有效的范围、限制、阻塞、下一步和完成条件。
每任务完成后将过程、关键决定和验证结论写入 `completed/<阶段名>/<任务编号>.md`，再更新计数与下一任务。
主计划已完成区只留完成状态与归档路径，不复制历史；未完成任务没有历史完成记录。
七阶段各使用独立历史目录；当前 `.gitkeep` 仅保留空目录，不代表任何工作已完成。
主计划控制在约 60–80 行；未来任务只保留一行范围与前置，轮到执行时再展开当前任务。
